# Generalization Design (arbitrary books & language pairs)

> Raw converged output of a 10× adversarial critique→ideation loop that started from a valid complaint: the pipeline's prompts and deterministic checks were over-specified for Ender's Game + Traditional Chinese (Taiwan). The goal was a pipeline for **arbitrary books and arbitrary source→target language pairs**.
>
> **This document is intentionally MORE than what the repo implements.** The loop converged on a rigorous but heavy apparatus (a config compiler, regex sidecars/exec files, a prompt-assembler + regex-executor, a config-validator, a family-template schema with linguist-authored token lists + competence probes, per-record ledger shards, ~50 sentinels). It is preserved here in full because it documents real cross-language failure modes and antigravity-specific defects (e.g. `$(cat …)` not expanding, overwrite-only `write_to_file`, `cp && grep` conflating infra-failure with CLEAN, and the `style-analyzer` re-emitting language-specific content no runtime fix can reach).
>
> **What the repo actually implements is the LEAN CORE** (see `docs/REDESIGN.md` and the `lexis-orchestrator` skill): a single `language-profiler` agent → an operator-reviewed `notes/language_profile.md`; source de-hardcoding of the committed prompts/skills (zh/Ender literals become labelled examples); deterministic checks parameterized by the profile that **declare their mode and degrade loudly** (`SKIP`/`LOW_CONFIDENCE`); and zh-TW demoted to a committed fixture under `docs/examples/en-zh-TW/`. The heavy apparatus below is **deferred future work** — adopt pieces only if a real multi-language run proves the lean core insufficient.
>
> The load-bearing principle (shared by both): **language-pair knowledge is per-project data, not hardcoded prompt text; every deterministic check is language-agnostic mechanism parameterized by that data and fails loudly when it does not apply.**

# Generalizing lexis to Arbitrary Books and Language Pairs (consolidated proposal, Loop 11)

## 0. Framing and root cause

The lexis pipeline encodes language-pair knowledge in three wrong places: inline in agent system prompts (Mandarin calque examples, zh-TW negation markers, particle lists, the literal keyword `terminal-particle usage`), inline in deterministic grep strings (CJK quote classes, Latin/CJK terminators, the Hanzi-vs-Latin script-mismatch fast path), and inline in the SKILL guidance files the orchestrator reads as operating procedure. This makes en->zh-TW the *spec* rather than one *instance*. zh-TW must become a committed fixture exercised by the same machinery that runs every other pair.

Ten loops of critique pruned the design. Loops 1-7 established the runtime-vs-source split and the keystone that `$(cat …)` shell expansion does not fire on antigravity. Loop 8 forced the linguist-authored template, the competence probe suite, and the two-phase regression grep. Loop 9 exposed that the proposed parametric `regex-executor` reintroduced the same shell-expansion defect via `${FIELD}`, that the monolithic append-only ledger is a correctness failure on antigravity's overwrite-only `write_to_file`, and that several config fields had no delivery path to their consuming agents. **Loop 10 establishes the deepest remaining structural admission: the de-hardcoding was never complete at the root.** The style-analyzer — the agent that *generates* `style_guide.md` for every project — was omitted from the coordinated commit, so it continually emitted fresh `terminal-particle usage` content that the downstream style-patcher fought chapter after chapter. Loop 10 also established that the FORBIDDEN CONSTRUCTIONS block, once the Mandarin defaults are deleted, is *empty* for every other pair (sending the primary-translator to its training-data calque priors), that `cp && grep` conflates copy-failure with no-matches (silently mapping infrastructure failure to CLEAN on the highest-stakes gates), that `agent_source_paths.txt` generated from the assembler's read trace scans the wrong files, that `drift_decisions.tsv` does not exist at Stage-B chapter 1, and that LLM materialization of `$TARGETFILE` reintroduces ungoverned path generation.

This consolidation absorbs the Loop 10 keystone corrections: **(1) the generator agents are fixed at the root via a single compiler-written `translation_constraint_seed.md` that every generator reads first — the style-patcher is retired; (2) all chapter-specific exec files are materialized by the compiler at Init time from `disbinder_structure.json`, so no agent ever performs path substitution; (3) the `cp` and `grep` steps are split into two sequential `run_command` calls with isolated exit codes, eliminating the conflation; (4) the agent-source list is a committed static manifest, not a runtime read-trace; (5) the FORBIDDEN CONSTRUCTIONS block is never empty and never defaults to Mandarin.**

### 0.1 Disciplines

1. **Two kinds of de-hardcoding, never conflated.** *Source de-hardcoding* is a one-time committed edit removing a hardcoded string from an agent/SKILL file, verified by Phase-1 regression over a committed static agent-source manifest (§9). *Runtime de-hardcoding* is per-project content the compiler assembles.
2. **Knowledge lives in compiled files, never in prompts or shell variables.** An operator-confirmed prose profile, machine-checkable family templates with committed linguist-authored token/category lists, and mechanically-validated artifacts are the runtime source of truth.
3. **No regex, no field name, and no path ever reaches a shell command as a variable.** The compiler writes one fully-materialized exec file per check *per chapter* with absolute paths baked in at compile time. The only token any agent ever handles at runtime is the path *to its own exec file*, received as a named argument — never interpolated mid-string. This is the Loop 9/10 keystone; the command reaching the shell is a string constant.
4. **Every deterministic check declares its mode and degrades loudly.** Inapplicable, low-confidence, or model-incompetent checks emit explicit `SKIP`/`LOW_CONFIDENCE`/`LM_COMPETENCE_LOW` advisories that gate the packager. Nothing silently passes; nothing silently fails. Infrastructure failures (copy failure, missing file) are distinct named sentinels, never mapped to CLEAN.
5. **Structural incompatibility is caught at compile time** via a committed compiler decision table before any exec file is written.
6. **No LLM certifies its own regex or vouches for its own competence.** PCRE validity is grep exit codes; semantic coverage is operator fixtures; model competence is a static linguist-authored probe suite (§2.9) with the memorization caveat declared.
7. **Cross-chapter state lives in per-chapter, per-record-type shard files written on `final/` text, queried by directory-glob grep** (§2.10). No append operation exists anywhere.
8. **Absent config is a hard Init failure**, except where an explicit conservative default or graded template tier (§8.1) declares a degraded-but-proceeding mode.
9. **Family templates are validated infrastructure with a committed schema** carrying token lists, calque categories, boundary-char sets, observation strategies, case counts, and per-check reliability (§8).
10. **Regression greps are two-phase**: agent-source at Init (Phase 1) against a committed static manifest, assembled-artifact-only at runtime (Phase 2), with an explicit committed exclusion list (§9).
11. **The pipeline declines mechanical quality claims it cannot support**: STUB/NONE template tiers and LM_COMPETENCE_LOW route to human-review with packager gates.
12. **zh-TW is a fixture reproduced by outcome vector; en-de is a mandatory, committed-at-deploy second worked example** on a same-script, compounding, inflecting pair.

All agents ship on **both harnesses** (antigravity `agent.json` + opencode `.md`); field and file names are identical because both read the same artifacts.

## 1. Where language-pair knowledge lives

In strict order of authority:

- **Human-authored per-book assets** (highest authority): `TRANSLATION_EXEMPLARS.md`, `POSITIVE_CONSTRAINTS.md`/PCD, `confirmed_names.md` (with `expected_variants[]`, `inflected_forms[]`, `grammatical_gender`, `SERIES_OVERRIDE`), `calque_prohibitions.md`, operator-owned `truncation_phrases.md`, `stopword_list.txt`, `register_exemplar_map.md`, `retained_forms.txt`, per-pair negation seed files. Authored in the target language; the primary quality lever and source of validation fixtures.
- **`templates/families/<family>.md`** + **`templates/family_template_schema.json`** + **`templates/families/<family>_probes.json`** — committed, linguist-authored, machine-checkable family infrastructure. The locus of all linguistically-critical token lists (negation tokens, calque categories, boundary chars, observation strategies, case counts).
- **`templates/agent_source_manifest.txt`** — committed static list of every agent source file path, maintained by engineers in the commit that adds or renames an agent (§9, §2.11).
- **`notes/language_profile.md`** — operator-reviewed prose draft, never authoritative.
- **`notes/language_config.json`** — compiled, validated, typed.
- **`notes/assembled/translation_constraint_seed.md`** — the single compiler-written language-pair constraint block read by every generator agent (§2.0).
- **`notes/assembled/ch{N}/<check>_exec.md`** — per-chapter, per-check fully-materialized command files with all paths baked in (§2.4).
- **`notes/assembled/<field>_regex.txt`** + per-check pattern-hash files; other assembled files (`packager_manifest.json`, `template_tier_effects.json`, `suspended_checks_manifest.json`, `INIT_COMPLETE` sentinel).
- **Per-chapter, per-record-type ledger shards** under `notes/ledger/` plus the Init-stubbed `drift_decisions.tsv` (§2.10).
- **Per-chapter sidecars** read directly by their consuming agent (`<file>.task_preambles.json`, `<file>.omission_config.json`, `ch{N}_relationship_shifts.json`, `ch{N}_source_override.json`).
- **Committed agent/SKILL source text** — generalized once and frozen; language knowledge enters a prompt only by the generator reading the seed file or the injector's per-chapter sidecars.

Prose never reaches a grep. **All linguistically-critical token lists are serialized by the compiler reading the template JSON directly — never via the profiler's prose** (an LLM transcribing a token list is generation that can drop or hallucinate tokens; the guarantee holds only if the compiler reads the template array).

## 2. New and rewritten agents

### 2.0 The constraint seed (`translation_constraint_seed.md`) — root-cause fix for generator over-specification
The compiler writes one per-project artifact that every generator agent (style-analyzer, primary-translator, final-translator) reads as its first `view_file`. It **replaces, not supplements**, the hardcoded blocks in those prompts. Three compiler-written sections, all from template JSON and operator assets, never from LLM prose:

- **Section 1 — FORBIDDEN CONSTRUCTIONS.** The template's `CALQUE_CATEGORIES` labels, each with one operator-authored exemplar sentence from `TRANSLATION_EXEMPLARS.md`, plus any `calque_prohibitions.md` entries. zh-TW reproduces 然而/大聲喊道/了-chains exactly (regression-asserted). en->de contains Germanic categories (`Schachtelsatz nominalization`, `false-friend lexical substitution`, `English light-verb passthrough`) with the operator's Schreibtisch example. **The block is never empty and never Mandarin-by-default:** a category with no matching exemplar -> `CALQUE_EXAMPLE_NEEDED: <category>`, which the Stage-B-entry injector halts on (`EXEMPLAR_GAP_UNRESOLVED`); a STUB-tier pair with no categories and no `calque_prohibitions.md` gets the single line `CALQUE_GUIDANCE: NONE — rely on native-critique PRIORITY CHECKS`.
- **Section 2 — REGISTER INSTRUCTION**, keyed on `register_instruction_mode`: `particle_enclitic` (zh-TW/ja: terminal-marker guidance, regression-asserted for zh-TW), `tv_distinction` (Romance/Slavic/Germanic-with-T-V: T-V per `formality_matrix.md`), `honorific_tier` (ja/ko: keigo/speech-level per matrix, per-utterance shift permitted), `lexical_register` (de/en/same-script: register via vocabulary and syntax, *no particle or T-V morpheme concept*). This is the string that replaces `terminal-particle usage` at the root.
- **Section 3 — LANGUAGE PAIR EXEMPLARS.** The compiler's verbatim register-tagged excerpt of `TRANSLATION_EXEMPLARS.md` — no LLM rewriting.

The **style-patcher is retired.** It fought a symptom while the root emitter was unfixed, introduced an operator ack-gate per chapter (a zh-TW throughput regression), and performed unvalidated LLM substitution. It survives only as a one-time migration no-op for in-flight pre-commit zh-TW projects (emits `STYLE_PATCHER_MIGRATION_COMPLETE`, then inert). The seed file is the single point of language-specific register framing, written from a committed enum, not LLM prose. Absent seed -> generators emit `CONSTRAINT_SEED_MISSING` and halt (named Init failure), never silently emit zh-framed guidance for a German project.

### 2.1 `language-profiler` (Init, after metadata-generator; `view_file, write_to_file`)
Emits `notes/language_profile.md` — operator-facing prose only, never the source of any machine-checkable field. It narrates the selected family template, locale, and source samples for operator review, surfaces the negation mode / register system / dialogue convention / named calque categories for operator confirmation, and emits `TEMPLATE_UNTESTED_FOR: <locale>` outside the validated set. Init gates do not pass until `COMPILER_VALIDATED`, `SEED_REVIEW_STEP_COMPLETED`, `PROFILE_CONFIRMED`, `CALQUE_REVIEW_CONFIRMED`, `LM_COMPETENCE_TRIAGED` exist.

- **Forced diglossic / written-standard disambiguation:** bare `ar` (MSA vs Egyptian/Levantine/Gulf), `zh` (zh-TW/zh-CN/zh-HK/yue), `no` (nb/nn) -> halt with `REGISTER_VARIANT_UNCONFIRMED` and force the metadata-generator to re-prompt. **The re-prompt is bounded** (Loop 10 halt-loop critique): a committed `max_reprompt_count` (default 2); on exhaustion, or when no human is attached (CI/CD), the profiler writes `DIGLOSSIA_UNRESOLVED_HALT` and refuses to proceed rather than looping infinitely or silently defaulting to MSA. **The operator-competence limit is declared explicitly:** an operator who affirms the wrong diglossic register selects a stilted MSA template that no check catches; the probe suite measures *model*, not *operator*, competence. This is a stated residual.
- **Locale overrides within a family** via the template's `LOCALE_OVERRIDES`; absent -> `LOCALE_OVERRIDE_MISSING`. **Wrong-family / isolate guard** -> graded tier (§8.1). **Multi-family contact languages** -> per-stratum templates with `STRATA_MAY_CONFLICT`.

### 2.2 `language-config-compiler` (Init, after profiler; `view_file, write_to_file, list_dir`)
Reads the confirmed profile, the **family-template JSON directly** (all token lists), and operator files; emits `language_config.json`, `translation_constraint_seed.md`, `register_voice_anchor.txt` (the Section-2 string also exposed standalone for the style-analyzer), the per-check `<field>_regex.txt` + pattern-hash files, the chapter-enumerated exec vault (below), `language_config_tests.json`, `packager_manifest.json`, `template_tier_effects.json`, the empty `drift_decisions.tsv` stub, the `agent_source_manifest.txt` existence-assert, and `INIT_COMPLETE`. Its task is JSON serialization, pattern-file emission, command-file emission, and fixture extraction; reasoning is prohibited from annotating regex correctness.

**Chapter-enumerated static exec vault (the Loop 10 keystone).** After writing the generic `<check>_regex.txt` files, the compiler iterates over every chapter path in `disbinder_structure.json` and writes `notes/assembled/ch{N}/<check>_exec.md` with the target path **baked in as a literal string at compile time** — no `$TARGETFILE` placeholder exists anywhere. Each exec file is:

- The literal word `SKIP` (inapplicable/incompatible/incompetent check), or
- A three-line file: line 0 a header `# TYPE: grep` + `EXIT_ON_CP_FAILURE: true`; line 1 `cp /home/user/lexis/notes/assembled/<check>_regex.txt /tmp/lexis_rx_<check>.txt`; line 2 `grep -cPf /tmp/lexis_rx_<check>.txt /home/user/lexis/final/ch{N}.xhtml`. No `${…}`, no `$(…)`, no variable token. Cross-chapter checks bake the directory glob (`grep -hPf /tmp/lexis_rx_tv.txt /home/user/lexis/notes/ledger/ch*_TV.tsv`) — `*` is shell glob, evaluated identically on both harnesses precisely because it is *not* a `${}` harness-layer token. Diff-mode checks get `# TYPE: diff` and their own exit-code semantics.

The prompt-assembler's role collapses to **inlining already-materialized per-chapter exec files** — zero substitution (§2.3). A partial vault (disk full mid-write) -> no `INIT_COMPLETE` -> Stage B cannot start; partial vaults are never a silent path. UPDATE mode re-runs the compiler for a single chapter slot (split-chapter discovery), overwriting only that subdirectory.

**Compile-time structural incompatibility guards (committed decision table; each writes `SKIP`):** `NEGATION_MODE_INCOMPATIBLE_WITH_INFLECTION`; `NEGATION_CO_OCCURRENCE_REQUIRED_UNSUPPORTED` (Finnish `ei`+connegative); `STOPWORD_DENSITY_UNRELIABLE_CLITIC_LANGUAGE` (ar/he/hi/fa, both sides); `STOPWORD_DENSITY_UNRELIABLE_COMPOUNDING_LANGUAGE` (de/fi); `STOPWORD_LIST_NEAR_EMPTY_AFTER_COLLISION` (en->es); `DIALOGUE_DELIMITER_TYPE: none` / `DIALOGUE_GRAMMATICALLY_BOUNDED`; plus the **extended `NEGATION_STRUCTURE.mode` enum** — `token | morphological | co_occurrence | verb_serialization (Yoruba/Igbo) | cleft (Welsh/Irish) | suprasegmental (tonal)` — each non-token/morphological mode routing to `SKIP` with a template `negation_anchor_text`, never a silent wrong-pass under a mislabeled value. **`BOUNDARY_CHAR_SKIP_UNICODE_SEGMENTATION_REQUIRED`** is a new decision-table branch for scripts where boundary characters are undefined (Thai) or non-ASCII (Tibetan tsek U+0F0B, Arabic ZWNJ) — these route PCD boundary checks to `SKIP` + HUMAN_REVIEW_BLOCK rather than a hard `TEMPLATE_BOUNDARY_CHAR_MISSING` Init failure.

**The Germanic negation path is now concrete** (Loop 10 MISSING). For en->de the compiler serializes the committed `negation_tokens` array `[nicht, kein, keine, keinen, keinem, keiner, keines, nie, niemals, niemand, nirgends, nirgendwo, ohne, weder, noch]` from `Germanic.md` into a PCRE alternation — a literal array serialization, not LLM generation. This satisfies `negation_mode: token` + `inflection_level: agreement` -> non-SKIP, gated by `>=2` committed seed sentences in `docs/examples/en-de/negation_seeds.txt` (validator asserts the file exists with `>=2` lines). Source-side English negation tokens come from a committed `EN_SOURCE_NEGATION` constant in the schema (`not, n't, never, no, without, none, neither, nor`), **with word-boundary anchoring** (`\b`) so `no` does not fire on `noble/noted/known`.

**Schema fields** (every field always present; `null`/`SKIP` never coerced to pass): `tier`; `grep_dialect: PCRE`; `unicode_mode`; per-regex `pcre_required`; `inflection_level`; `inflection_case_count` (new integer, required for `case_marking|agglutinative`, feeds `fixer_drain_K`); `compounding_productive`; `compound_boundary_chars` (or `SKIP`); `stray_detection_strategy` (`mode`, static Unicode-block ranges, `closely_related_pair`, `mixed_script_target` (new, for Serbian/Uzbek/Kazakh dual-script), `stopword_density_threshold` or `null`, `min_usable_stopwords`); `negation_mode`/`negation_regex`/`source_negation_regex`/`negation_asymmetry`; `dialogue_pattern_type`, `dialogue_open_chars[]`/`dialogue_close_chars[]` (**per-locale, distinguishing German U+201E-opening from Hungarian U+201E-closing**), `dialogue_boundary: typographic|grammatical`, `dialogue_subtype` (new: `TYPOGRAPHIC_EM_DASH` vs `GRAMMATICAL_REPORTED_SPEECH` — so em-dash MSA literary Arabic gets an active count rather than a blanket SKIP), `dialogue_count_protocol`, `rtl_line_anchor`; `sentence_terminator_regex` **per side** (Spanish `¡¿` excluded; MSA/Urdu/Tibetan distinct sets; `abbreviation_negative_lookbehind` per pair for Sr./Dr./bzw.); `count_mode`; `paragraph_boundary_mode`; `register_marker_regex`/`register_instruction_mode`; `formality_tiers` + `formality_tier_labels[]` (Korean's six levels enumerated); `tv_observation_strategy` (enum extended — §2.10); `omission_length_ratio_tolerance` with **both `compounding_shortening_adjustment` and `expansion_lengthening_adjustment`** (the latter for ar/fi/he/tr/hu, which expand relative to English — Loop 10 MISSING) and `genre_sensitive`; `truncation_regex` + `truncation_fallback_regex` (below); glossary caps; `fixer_drain_K`.

**The truncation fallback is now specified** (Loop 10 highest-stakes MISSING). The packager/detector truncation check is `truncation_regex` (from `truncation_phrases.md` + template `TRUNCATION_MARKERS`, min 2) OR-ed with a committed **multi-script `truncation_fallback_regex`**: ASCII bracket forms `\[(truncated|omitted|aborted|incomplete|continued|TK|TODO)\]` AND the template's `FALLBACK_TRUNCATION_TOKENS[]` per family (Germanic: `abgebrochen|gekürzt|ausgelassen`; Romance: `truncado|omitido|cortado`; Semitic: `ناقص|مقطوع`). The fallback is family-derived, not a Latin-only assumption. Thin coverage -> `TRUNCATION_COVERAGE_LOW` ack gate; the named alternative signal is the omission-detector's paragraph-count deficit on the final chapter.

**Fixture extraction & ordering gate.** Per regex field: `{field_name, regex, fixture_match, fixture_nonmatch, fixture_source, safe_fallback}`, **prohibited from inventing fixtures for negation and dialogue** (safe_fallback always `SKIP`), extracting from `TRANSLATION_EXEMPLARS.md`, then operator seeds, then `original/` chapter 1. Absent exemplars -> `SEED_SENTENCES_NEEDED`, the dated-per-chapter `EXEMPLARS_AUTHORED_OR_DEFERRED` Init step.

### 2.3 `prompt-assembler` (Init + Stage B entry; `view_file, write_to_file, list_dir` — no run_command)
Inlines each pre-materialized per-chapter `<check>_exec.md`'s literal command lines into `notes/assembled/ch{N}/orch_assembled_steps.md` as named shell-script blocks. **It performs zero substitution** — the paths are already baked by the compiler — so the Loop 9 path-generation risk is eliminated, not merely guarded. It writes the `## Language-Specific Guidance` blocks consumed by the injector and writes `notes/assembled/chapter_path_manifest.txt` (the absolute path of each chapter's target, for the path-correctness pre-check). SKIP exec files inline as no-op comment blocks. Drift detection is not the assembler's responsibility.

### 2.4 `check-runner` (Stage B; `view_file, run_command, write_to_file`)
A judgment-free dispatcher with a **two-phase cp-isolated protocol** (Loop 10 keystone). For a named check it:

1. `view_file notes/assembled/ch{N}/<check>_exec.md`. Line 1 = `SKIP` -> write `SKIPPED`; no `run_command`.
2. **Path pre-validation (proactive, before any cp).** Read `disbinder_structure.json`'s chapter list; assert the exec file's baked target path appears in it. Mismatch -> `ASSEMBLER_PATH_NOT_IN_STRUCTURE: ch{N}` (a `view_file` + string check, no run_command). This catches a compile-time enumeration error before any flood of grep errors.
3. **Phase A — materialization.** `run_command('cp <src> <dest>')` **alone, no `&&`**. Exit 0 -> proceed. Exit non-zero -> `PATTERN_FILE_COPY_FAILED: <check>: exit <n>` and halt that check — structurally distinct from CLEAN and from GREP_EXECUTION_ERROR. For a hard-gate check (NEVER_USE, truncation) this degrades to HUMAN_REVIEW_BLOCK, never silent pass.
4. **Phase B — execution.** `run_command('grep -cPf <dest> <target>')` as a separate call. Exit 0 = MATCHES_FOUND:`<count>`; 1 = CLEAN; 2 = `GREP_EXECUTION_ERROR` with a three-way sub-code: pattern file absent -> `PATTERN_FILE_MISSING` (re-run Phase A); target absent -> `TARGET_FILE_MISSING` (assembler/structure error; for `drift_check` chapter 1 this would fire but the Init stub of `drift_decisions.tsv` prevents it — the file is present, grep returns 1); both present, grep exits 2 -> `PCRE_COMPILATION_FAILURE` (-> `PCRE_REQUIRED_SKIP` if `pcre_required`, else literal-string fallback). After a successful cp, check-runner verifies the pattern file is non-empty (`grep -c . <dest>` vs the committed pattern-hash line count) -> `PATTERN_FILE_EMPTY` rather than a silent no-match.

`# TYPE: diff` skips Phase A (no pattern file) and applies diff exit semantics. The command reaching the shell is always a string constant plus baked absolute paths; the two-call split changes only when the shell exits, not how it evaluates either command — harness-identical. When `normalization_available: false`, checks needing a normalized copy are forced SKIP (`SENTENCE_TERMINATOR_ENCODING_SKIP`), never a false zero.

### 2.5 `language-config-injector` (Stage B, once per chapter, before primary-translator; `view_file, write_to_file, list_dir`)
The sole runtime delivery point for per-chapter overrides and **owner of every config-to-agent delivery file** (the orchestrator has no read primitive to inline values). Reads `language_config.json`, `calque_prohibitions.md`, `register_exemplar_map.md`, PCD, `ch{N}_source_override.json`, `lm_competence_report.json`, `suspended_checks_manifest.json`, and writes:

- `notes/<filename>.task_preambles.json`: per-chapter `calque_permit[]` carve-outs, `native_critique_static_anchors`, `mechanical_checks_suspended`, `lm_competence_anchors`, the per-chapter `tv_observation_strategy` instruction, `negation_anchor_text`. Includes a self-check counting top-level items; divergence -> `INJECTOR_CONTENT_LOSS` advisory (acknowledged as an LLM self-count, with config-validator's Init grep as the authoritative backstop).
- `notes/<filename>.omission_config.json`: `{tolerance, genre_adjustment, compounding_shortening_adjustment, expansion_lengthening_adjustment, dialogue_density_tag, per_scene_verse_modes[], fixer_drain_K}` — read by the omission-detector as its **first** `view_file` (its prompt is edited to read this file before `original/`/`draft/`).
- Halts with `EXEMPLAR_GAP_UNRESOLVED` if the seed contains `CALQUE_EXAMPLE_NEEDED`.

Per-chapter calque permits are *additive overrides* on top of the seed's FORBIDDEN CONSTRUCTIONS, never replacements. `STATUS: ERROR` -> hard per-chapter halt.

### 2.6 `config-validator` (Init; `view_file, run_command, write_to_file`)
1. **Config field validity & coverage**; the spec-count constant is a declared maintenance tension and is treated as advisory beneath the structural check (Loop 10: it adds no verification value over the structural check and drifts within weeks).
2. **Command-shape check**, mechanically precise: `grep -cP '\$'` against every exec file must return 0 (no `$` tokens at all, since the compiler bakes all paths) -> `ASSEMBLED_COMMAND_MALFORMED` on any hit.
3. **Path-correctness check:** assert every entry in `chapter_path_manifest.txt` appears in `disbinder_structure.json` -> `ASSEMBLED_PATH_NOT_IN_STRUCTURE` hard Init failure before Stage B.
4. **Family-template schema check.** JSON-schema binary preferred; **absent the binary, a committed grep/view_file structural floor** asserts required fields present and **non-empty as arrays where applicable** — the floor is extended (Loop 10) to reject `negation_tokens: []` / `""` via a pattern requiring `[` followed by a non-`]` character, and to validate enum membership of `tv_observation_strategy`/`register_instruction_mode` against committed value lists, and the cross-field constraint that `gender_invariant: true` entries carry a non-null `gender_invariant_attestation` and that `co_occurrence_required: true` carries `safe_fallback: SKIP`. The grep floor cannot fully replace the binary, which is the recommended operator prerequisite, but it now catches empty-array, bad-enum, and the named cross-field cases.
5. **Init-output completeness:** `drift_decisions.tsv` stub, `agent_source_manifest.txt` existence, vault completeness per `disbinder_structure.json`. Missing stub -> `DRIFT_STUB_MISSING`; missing manifest -> `AGENT_SOURCE_MANIFEST_MISSING`.
6. **Two-phase regression grep** (§9).

### 2.7 `relationship-mapper` (Stage A, conditional on `formality_tiers >= 3`)
Produces `notes/formality_matrix.md` keyed `(speaker, addressee, scene_context)` with a value column whose domain is `formality_tier_labels[]` (Korean's six levels representable; the ledger record schema (§2.10) carries an n-ary `FORMALITY_TIER` column, not a binary T-V field, so cross-chapter comparison of six-level Korean produces meaningful conflicts rather than false ones). Documented as a **scene-level floor**: native-critique PRIORITY CHECKS are told keigo/honorific tier may shift per utterance, which the matrix does not resolve. **English-source blindspot declared:** the matrix is seeded from English, which encodes neither T-V nor keigo; the mapper infers social dynamics from narrative context, character descriptions, and scene framing (its read set is `summary.txt`, `scenes.md`, and the chapter source), emitting `SOCIAL_RANK_AMBIGUOUS: <pair>` when the source underdetermines rank rather than guessing. Target-only and per-utterance shifts route to native-critique and the ledger. The architecture does not claim mechanical keigo correctness.

### 2.8 `lm-competence-trier` (Init, after compiler, before config-validator; `view_file, run_command, write_to_file`)
Measures whether the mid-tier model can produce reliable verdicts in the target language before the pipeline trusts them. Reads `language_config.json`, the lang tag, and the committed `templates/families/<family>_probes.json`. Writes `notes/lm_competence_report.json` with per-check `confidence: VERIFIED | UNVERIFIED | LOW | SKIP` for `stray_detection`, `negation_parity`, `register_assessment`, `fluency_scoring`, **and `native_critique_negation`** (added so the same-script backstop's reliability is itself measured).

- **Grep-executable probes** run the compiled exec against a probe corpus vs a committed expected count.
- **Competence probes** show a committed flawed sentence, ask the model to identify the flaw, compare by tagged-token match with an accepted-synonym set (reduces surface-form false-LOWs).
- **Probe selection within a family** is explicit (Loop 10 gap): `<family>_probes.json` carries a `lang_tag` index; the trier runs only the subset matching the project's tag — Mandarin sentence-final-particle probes for zh-TW, keigo (sonkeigo/kenjougo/teineigo) probes for ja, diglossic-stratum probes for ar — never all CJK probes on every CJK pair.
- **Per-register, not per-script coverage:** each register system within a family gets its own probe. **Romance probes are a launch requirement** (Loop 10): `Romance_probes.json` must cover French T-V, Spanish vos/tuteo, and Brazilian/European Portuguese formal register for Romance to reach PARTIAL/FULL — otherwise en->fr/es operate with `register_assessment: UNVERIFIED` and native-critique doing 100% of register work with no competence bound, a declared cliff for T-V-sensitive literary French.

**The memorization caveat is declared:** VERIFIED bounds-from-below (training-data coverage, not per-utterance correctness in unseen text). Downstream gates: config-validator forces any `LOW` check to `SKIP` with `LM_COMPETENCE_LOW`; the packager's non-waivable Model Competence section lists each LOW check with its probe-failure and compensating anchor. The zh-TW fixture acceptance criterion requires VERIFIED only on the **Mandarin** probes (Loop 10: the keigo probe is a spurious dependency for zh-TW and must not gate it).

### 2.9 Per-chapter shard ledger + `consistency-snapshot-writer` + `index-builder` (Stage B close)
Eliminates the monolithic append-only ledger and the Stage-A draft-that-does-not-exist contradiction.

- **`consistency-snapshot-writer`** runs in Stage B **after `final-translator` writes `final/<filename>`** — observing shipped text. It reads `final/<filename>`, `ch{N}_relationship_shifts.json` (**producer specified:** the narrative-summarizer, whose output set and prompt are edited to emit `speakers[]`, `addressees[]`, `social_dynamic`, `RELATIONSHIP_SHIFT`, `source_retain[]`, and verse tags — closing the silent missing-input gap), and its injected `tv_observation_strategy`, and writes per-chapter, per-record-type shards via **single full-overwrite `write_to_file` calls** (no append, O(1)): `notes/ledger/ch{N}_TV.tsv`, `ch{N}_GENDER.tsv`, `ch{N}_GLOSSARY.tsv`, each ending `# END ch{N}`. Re-run overwrites only that chapter's shards (idempotent). Missing terminal sentinel -> `SHARD_INCOMPLETE: ch{N}`.
- **T-V/formality observation is strategy-driven.** The shard's `CONFIDENCE` column is `HIGH | PARTIAL | ABSENT`. The `tv_observation_strategy` enum is **extended** (Loop 10): `morphological` (Russian — unambiguous 2-person endings -> HIGH), `morphological_with_mandatory_subject` (French — non-pro-drop; `tu manges`/`vous mangez` endings *and* obligatory explicit pronouns both qualify HIGH, fixing the false PARTIAL-suppression that `explicit_pronoun_only` caused for French), `explicit_pronoun_plus_imperative` (Spanish/Italian/Portuguese pro-drop — HIGH only on explicit `tú/usted/vos/vous`/imperatives/vocatives; `vos` vs tuteo -> PARTIAL), `inapplicable` (Japanese -> matrix-only). **The structural blind spot is declared:** for pro-drop Romance, consistent pro-dropping yields sparse HIGH entries, so real cross-chapter honorific drift can be invisible to the auditor; native-critique (per-chapter) is the acknowledged sole fallback, and `TV_COVERAGE_SPARSE: <relationship>` is emitted so the gap is visible rather than hidden.
- **`index-builder`** (book-wide, before the auditor). **Capacity is addressed** (Loop 10): for an N-chapter book, 3N `view_file` calls overflow context on long books and the agent has no `run_command`. The fix: `index-builder` runs as a **bounded multi-turn loop in batches of B chapters** (B committed, default 10), each batch appended to `LEDGER_INDEX.txt` by a single full-overwrite of the growing index it carries forward; on the final batch it writes the `# INDEX COMPLETE N` sentinel. A missing sentinel -> `LEDGER_INDEX_INCOMPLETE`, never a silent truncation. **The index's purpose is narrowed:** the auditor queries shards by directory-glob grep directly and does not need the index for content; `LEDGER_INDEX.txt` exists only as the shard-count manifest the auditor pre-checks against `disbinder_structure.json`, and as the destination for `series_prior_GLOSSARY.tsv` and `drift_decisions.tsv` writes in `mode: drift_record`. (Acknowledged: a directory listing could serve the count, but the index also carries the series-prior and drift records, justifying the agent.)
- **The `consistency-auditor` queries by directory-glob grep** via baked exec files; it flags conflicting `HIGH` `TV_ASSIGNMENT`/`FORMALITY_TIER` across chapters, `GENDER_USE` conflicts, and `GLOSSARY_USE` against `expected_variants[]` with the `series_prior` baseline and current-book-wins-unless-`SERIES_OVERRIDE` policy. For **Arabic RTL** the auditor's own glossary-term greps are routed through baked exec files with `unicode_mode` flags rather than self-formed patterns, and glossary values carry compiler-inserted bidi marks stripped before grep (§ below). Japanese honorific drift across chapters has no ledger TV path (`inapplicable`) and is routed to native-critique with the declared limitation that native-critique is single-chapter — a stated open gap for cross-chapter keigo consistency.
- **PROFILE_DRIFT without an orchestrator grep:** `drift_check_exec.md` (baked path against the Init-stubbed `drift_decisions.tsv`) is run by config-validator at each Stage-B chapter entry; the stub guarantees grep exit 1 (not 2) from chapter 1. It writes a `DRIFT_DECISION_FOUND`/`DRIFT_DECISION_ABSENT` sentinel the orchestrator reads from a named output file.

Both-harness parity: every ledger op is a single full-overwrite `write_to_file` or `view_file`; every query is a directory-glob `grep -hPf` via check-runner. zh-TW exercises `TV_ASSIGNMENT` via explicit 您/你 (HIGH, unaffected by pro-drop carve-outs); en-de exercises a Sie/du conflict across three committed shards.

### 2.10 RTL and bidi handling for greppable artifacts
For en->ar the glossary and ledger values are RTL. The compiler and glossary-manager insert bidi marks (`U+200F`/`U+200E`) **only into display-facing fields** (`usage_notes`); **grep-target fields** (`translation`, canonical forms used in audit greps) are stored without bidi marks, and exec files that grep these fields are compiled with `unicode_mode` PCRE flags. Agents never self-construct RTL grep patterns from terminal display: all RTL greps are compiler-baked exec files, so the LLM-bidi-reversal-on-pattern-construction problem (an agent visually reordering Arabic when composing a command) is structurally avoided — the agent runs a file, it does not type the pattern. RTL line-number reporting in stray reports is flagged with a `RTL_LINE_NUMBERS_LOGICAL` advisory so the operator knows reported line numbers are logical-order, not visual-display-order.

### 3.1 REPAIR_MODE split on match-type, gender, boundary
- **EXACT_FORM** (left+right bounded by `compound_boundary_chars`): `REPAIR_BLOCK` for `TOKEN` + `none|agreement`; a NEVER_USE term opening a hyphenated compound (`NEVER_USE-Kabel`) -> `COMPOUND_CONSTITUENT_ADVISORY`.
- **TEMPLATE_SENTENCE**: `REPAIR_BLOCK` verbatim only when `gender_invariant: true` **with a non-null `gender_invariant_attestation`** that the config-validator now hard-enforces as a cross-field constraint (§2.6.4). A mistagged gendered entry remains a declared residual the validator cannot semantically verify; **the en-de fixture exercises both a correctly-tagged invariant entry AND an incorrectly-tagged gendered entry that must route to HUMAN_REVIEW_BLOCK** (Loop 10: the negative case must be tested, not only the positive).
- **Inflected EXACT_FORM in case-marking targets / `compound_boundary_chars: SKIP` / Unicode-segmentation scripts** -> `HUMAN_REVIEW_BLOCK`, never default-REPAIR.

**Fixer-drain bound is concrete** (Loop 10 MISSING): `fixer_drain_K = min(50, 5 * inflection_case_count)`, computed at compile time, written to `omission_config.json`. `NEEDS_HUMAN_TRANSLATOR` fires when pending blocks exceed K after the fixed drain sequence (glossary-queue drain, then fixer-review drain, then overflow checks). Absent `inflection_case_count` (PARTIAL/STUB) -> K=50 + `DRAIN_K_DEFAULT_APPLIED`. When `FIXER_REVIEW_PENDING` remains, the orchestrator writes `FIXER_PENDING: ch{N}` and the **translation-scorer prompt is edited to read it** (the scorer has grep:deny; it reads the marker via `view_file`), annotating Adequacy `SCORE_ON_UNRESOLVED_DRAFT`; the packager NEVER_USE gate on `final/` is the hard backstop.

### 3.5 Same-script / skipped-stray packager gate
When stray-source, negation parity, and the register gate are all SKIP (en->de/es/fr norm), native-critique is the sole backstop, made loud:
- `suspended_checks_manifest.json` carries a `compensating_anchor` per suspended check; the injector promotes each into a numbered `## PRIORITY CHECKS` block.
- native-critique emits `STRAY_CONTENT_WORDS_CHECKED: <count>` as its **last line**; absence -> `NATIVE_CRITIQUE_INCOMPLETE`. **"Content word" is defined per family** in the template (`CONTENT_WORD_DEFINITION`: whitespace tokens minus stopwords for analytic languages; stem-bearing tokens for compounding; root-bearing for Semitic) and a **minimum coverage floor** (`min_content_words_checked`, e.g. >= 20 or the chapter's full content-word count if smaller) below which the check is `NATIVE_CRITIQUE_COVERAGE_INSUFFICIENT`, so a token count of `3` no longer passes.
- `stray_detection: LOW` -> `LM_COMPETENCE_LOW: stray_detection`; the en->es residual (two untranslated paragraphs passing every check) is stated, bounded, packager-visible — a declared cliff the architecture does not fully solve.
- **Code-switching / third-language retention** (Loop 10): `ch{N}_source_override.json` gains `source_retain[]` (intentional source-language passages) **and `third_language_retain[]`** (Latin epigraphs in an en->de book, Russian names in ja dialogue — same-script or different-script passages in neither source nor target). The injector subtracts both span sets from stray expectations and from native-critique's content-word denominator.
- The scorer's `IDENTICAL_LANGUAGE_ADVISORY` consults confirmed transliterations and `retained_forms.txt`; **the scorer prompt is edited to read `retained_forms.txt` as a conditional input** (Loop 10: previously the guard was inert — the scorer prompt never listed the file). The scorer samples 3-5 passages by LLM judgment and cannot guarantee catching a mid-chapter untranslated block; this limit is declared, not papered over.

### 3.6 Bidi-control scrub under file-IPC
A scrub requiring operator review for an undefined numeral-run span cannot interrupt-and-resume mid-agent under file-IPC. The disbinder writes a `BIDI_SCRUB_REVIEW_PENDING: <file>:<span>` sentinel and halts; the orchestrator's halt-loop step reads the sentinel and routes to operator review, resuming only after an operator-written ack file appears. This is an asynchronous sentinel-write + orchestrator-poll, not a synchronous blocking gate; the step is now specified rather than implied.

### 3.7 SCORER_CONFIDENCE gating
When the fluency probe is LOW the scorer prepends `SCORER_CONFIDENCE: LOW` and disables the calibration downgrade-to-sampling. **Additionally** (Loop 10): the orchestrator's Step 4.5 regression gate does not compare the LOW-confidence numeric score against the prior chapter; instead it routes to `FLUENCY_HUMAN_CONFIRMED` review, so an unreliable score cannot silently gate chapter progression by happening to land above threshold.

### 3.8 EPUB structural edge cases
- **Non-linear spine items** (`linear="no"` footnotes/endnotes/appendices): the disbinder tags them in `disbinder_structure.json` with `linear: false`; they are included in translation scope but excluded from the chapter-count parity check the auditor runs, resolving the count-mismatch-or-invisible dilemma.
- **EPUB chapters split across XHTML files**: the disbinder emits `SPLIT_CHAPTER_DETECTED: <ids>` at Init (a named sentinel before Stage A) so the operator chooses merge-or-treat-separately, rather than discovering it mid-Stage-B with no recovery path.
- **Thai/`<br/>`-delimited paragraphs**: the disbinder runs a structural-normalization step converting `<br/>`-runs to `<p>` where heuristically safe; where unsafe -> `PARAGRAPH_MODE_UNRECOGNIZED` with the escalation path now defined as operator-supplied paragraph-boundary rules in `disbinder_overrides.json`, after which omission falls back to native-critique paragraph alignment.
- **Dialogue-quote-free English source** (Cormac McCarthy): the dialogue structure-floor is `SKIP` with `SOURCE_DIALOGUE_CONVENTION_ABSENT` rather than propagating a wrong count downstream.
- **Mixed prose-and-verse chapters**: `omission_config.json` carries `per_scene_verse_modes[]` so the omission-detector applies verse tolerance per scene rather than averaging one verse scene into ten prose scenes.

### 3.9 Verse and degenerate Tier-3
Verse mode exempts both structure-floor and line-count matching; quality routed to native-critique. No-space-segmented degenerate single-paragraph -> `STRUCTURE_FLOOR_DEGENERATE` -> omission paragraph-alignment + native-critique.

## 4. The de-hardcoding mechanism

Runtime chain: compiler writes `<field>_regex.txt` + the chapter-enumerated exec vault + `translation_constraint_seed.md` -> `prompt-assembler` inlines literal command lines (zero substitution) -> `check-runner` runs `cp` then `grep` as two isolated calls -> caller reads the result. **No `${…}`, no `$(…)`, no field-name or path variable anywhere.**

**Source de-hardcoding (one coordinated commit).** All over-specified clusters de-hardcoded atomically: primary-translator and final-translator FORBIDDEN CONSTRUCTIONS and the `defaults for Mandarin` parenthetical (replaced by reading seed Section 1); **style-analyzer** (the root emitter — replace `terminal-particle usage` with reading `register_voice_anchor.txt`/seed Section 2; this was the Loop 10 keystone omission); stray-phrase-detector Tasks 8/9 (deep prompt rewrite — the negation/particle markers are inline instructions the agent forms greps from; the rewrite instructs reading the baked exec file and **the detector runs its own grep via run_command** rather than going two hops through check-runner, resolving the dual-role ambiguity — the detector remains the antigravity orchestrator's grep proxy and reads exec files directly; its own hardcoded CJK truncation grep is deleted); orchestrator SKILL greps (Step 4.0a CJK dialogue/terminator, Step 4.2b TW-particle re-invocation); native-critique (the entire negation-check instruction block is **nulled and replaced** when `negation_mode != token`, not augmented — avoiding the LLM applying both old CJK and new anchor); the SKILLs (`lexical-management`, `translation-validation` — relabeled language-neutral, the script-mismatch description rewritten to instruct reading the assembled check type rather than inline knowledge); glossary-manager, metadata-generator, omission-detector, translation-scorer, narrative-summarizer, consistency-auditor, ebook-packager prompt edits (§7).

**The Step 4.0a scene-resolution sequencing gap is resolved** (Loop 10): scene resolution precedes chapter-exec materialization, but the vault is built at **Init** (not Stage-B entry), so the per-chapter structure-floor exec files already exist when scene resolution runs; the orchestrator dispatches them via check-runner (opencode) or the stray-phrase-detector proxy (antigravity) using the already-materialized files. No inline grep remains.

**The catch-22 is addressed.** Phase-1 regression cannot run until the de-hardcoding commit lands; the mitigation is that the source-de-hardcoding commit and the new-agent additions are **one atomic deploy gated by both worked examples passing**. The acceptance criterion: Phase-1 returns zero over `agent_source_manifest.txt` AND both the zh-TW and en-de fixtures reproduce their outcome vectors. Until met, the legacy zh-TW-only pipeline remains the only supported configuration. **A per-chapter zh-TW regression check on the assembled FORBIDDEN CONSTRUCTIONS block** (a baked grep asserting the seed Section 1 still contains 然而/了-chains/電子桌 for `lang_tag: zh-TW`) runs at Init, closing the quality-regression window between commit and fixture completion (Loop 10).

**Coverage audit before deletion.** Inline zh-TW guidance is deleted only after a committed line-by-line prompt-coverage audit mapping every guidance item to its seed/assembled destination; the en-de fixture exercising every destination block is the enforcement gate.

## 5. Mid-tier model + operator review keeping the profile reliable

1. **Split hard from easy.** Recall (profiler) unreliable; serialization (compiler reading template JSON) reliable; structural compatibility by committed decision tables; regex correctness by execution; coverage by operator fixtures; competence by the probe suite. The hardest fields (agglutinative/co-occurrence negation, morphosyntactic register, inflected forms, calque categories, negation tokens, `tv_observation_strategy`, boundary chars, case counts, bidi numeral-run criteria, content-word definitions) are **template-supplied by a linguist**, not profiler-generated.
2. **Mechanical validation on both harnesses** via config-validator: structural completeness, the `$`-token command-shape grep, path-correctness against `disbinder_structure.json`, JSON-schema validation (binary preferred; extended grep floor catching empty arrays / bad enums / the named cross-field constraints), the two-phase regression grep.
3. **Operator confirmation is a hard gate with affirmative, file-scoped preconditions.** `PROFILE_CONFIRMED` names the calque file, family, `closely_related_pair`, the diglossic register, and coverage flags. `CALQUE_REVIEW_CONFIRMED` requires `>=1` entry per category. **The non-fluent-operator limit is declared and partially mitigated:** the probe suite is the architectural substitute for review competence the operator lacks, and `gender_invariant_attestation` plus the bounded diglossia re-prompt make the residual authoring/affirmation risk visible — but an operator affirming the wrong diglossic register is a stated unsolved gap (no check catches MSA-vs-Egyptian audience mismatch).
4. **Versioning without an in-context hash.** opencode `sha256sum`; antigravity check-runner diff-mode. `PROFILE_DRIFT_ACKNOWLEDGED` via the Init-stubbed `drift_decisions.tsv` read by config-validator's drift exec — no orchestrator grep.
5. **UPDATE mode + backward-propagation.** Recompiles only affected exec/regex/config/vault-slot; shards are idempotent overwrites. `INIT_COMPLETE` + `LEGACY_PACKAGER_FALLBACK`: **the packager migration is staged** (Loop 10) — the CJK truncation grep removal and the INIT_COMPLETE gate are not the same atomic step; a minimal `truncation_exec.md` (using `truncation_fallback_regex`) is produced even for pre-generalization projects at first UPDATE, so no project is left with no truncation gate after deploy.
6. **Low-resource graduation.** `scorer_confidence: low` requires `FLUENCY_HUMAN_CONFIRMED`; the calibration downgrade is disabled when the fluency probe is LOW; the regression gate routes to human confirmation rather than the unreliable numeric score (§3.7).
7. **Consolidated manifests.** The packager's **Suppressed Checks and Waivers** and non-waivable **Model Competence** sections list every waived/LOW check with sentinel path and timestamp.

**Regression baseline** = the PASS/WARN/UNVERIFIED/competence outcome vector + `<field>_regex.txt` + the exec vault + `translation_constraint_seed.md` + ledger shards + two-phase regression results, compared `jq -S`/line-by-line. **The en-de second worked example is a deploy prerequisite**: profile, config, exec vault, seeds, stopword list, register map, fixtures, `Germanic_probes.json`, a correctly-tagged `gender_invariant` entry with attestation, an **incorrectly-tagged gendered entry routing to HUMAN_REVIEW_BLOCK**, a compound case (`Schreibtischlampe`), a left-boundary hyphen case (`Schreibtisch-Lampe`), an inflected NEVER_USE (`Schreibtischs` -> HUMAN_REVIEW_BLOCK), a Sie/du conflict across three shards, the serialized Germanic negation alternation with `>=2` seed sentences, and `omission_length_ratio_tolerance` with both shortening and lengthening adjustments. **A committed PARTIAL/STUB-tier fixture** (a minimal isolate or under-resourced pair) is added so the graded-tier mechanism is validated rather than merely specified (Loop 10). Both worked examples plus the tier fixture are living integration tests that gate the deploy.

## 6. Typological tier contract

Tier governs **only counting/segmentation defaults** — orthogonal to `inflection_level`, `stray_detection_strategy.mode`, `negation_mode`, `register_instruction_mode`, `tv_observation_strategy`, and the template-completeness tier (§8.1). Tier 1 (reliable terminators + segmentable): zh-TW, Japanese. Tier 2 (morphologically rich): target-canonical glossary via ledger; negation often compile-SKIP. Tier 3 (no-space-segmented, unreliable terminators): `paragraph_only`; degenerate -> `STRUCTURE_FLOOR_DEGENERATE`.

## 9. Two-phase regression grep

**Phase 1 — commit-time agent-source scan against a committed static manifest.** `templates/agent_source_manifest.txt` lists every agent source file path, maintained by engineers in the commit that adds/renames an agent — **not generated from the assembler's read trace** (the Loop 10 fix; the assembler never reads agent source, so a generated manifest scanned the wrong files). The compiler writes `hardcoded_zh_patterns_regex.txt` from a committed static codepoint list (`terminal-particle`, U+4E0D/U+6C92/U+5225/U+672A, U+554A/U+5594/U+561B/U+5427, `電子桌`/`課桌`); config-validator runs the baked `phase1_exec.md` (`cp` + `grep -cPf` over each manifest path); a hit -> `AGENT_PROMPT_STALE: path:line`, hard Init failure. Absent manifest -> `AGENT_SOURCE_MANIFEST_MISSING`. **The structural skew is declared** (Loop 10 quality): the pattern list catches only CJK de-hardcoding failures; it does not catch a hypothetical hardcoded MSA or French token in an agent prompt. The mitigation is that no agent prompt currently contains non-CJK language tokens and the seed-file architecture means new language knowledge enters via compiled files, not prompts; a family-appropriate regression pattern per family is named as future work rather than claimed solved. The manifest excludes `docs/examples/` (read only by the fixture harness, never as agent source) so fixture CJK content never false-positives Phase 1.

**Phase 2 — runtime assembled-artifact scan, scoped.** Greps only `notes/assembled/`. The exclusion list `notes/regression_exclusions.txt` lists operator-authored paths (`calque_prohibitions.md`, `TRANSLATION_EXEMPLARS.md`, `stopword_list.txt`, `register_exemplar_map.md`, `retained_forms.txt`) plus the `docs/examples/**` glob; a drift check asserts the exclusion list's example-file count matches the actual `docs/examples/` count. **The legitimate-CJK-in-assembled case is handled** (Loop 10): an en->de book with Japanese character names transliterated into Kanji would write Kanji into `glossary_audit_regex.txt`; Phase 2 distinguishes the committed zh-TW pattern set (specific function-word/particle codepoints) from arbitrary CJK, so a proper-noun Kanji does not false-positive `ASSEMBLED_ARTIFACT_STALE` — the pattern list is the zh-TW grammatical-marker set, not "any Hanzi."

Both phases use baked exec files via `cp`+`grep -cPf` (no shell expansion), fixing both the false-positive (Phase 2 no longer fires on legitimate operator zh-TW content) and the false-negative (Phase 1 catches a hardcoded string in agent source even when the injector produced clean output).

## 10. The decisive Loop 10 difference

Loop 9 eliminated parametric dispatch by baking absolute paths into per-check command files; Loop 10 closes the gaps that still let the static-dispatch guarantee leak. The generator agents are fixed at the **root**: a single compiler-written `translation_constraint_seed.md` supplies FORBIDDEN CONSTRUCTIONS (never empty, never Mandarin-default) and a mode-keyed REGISTER INSTRUCTION (no `terminal-particle usage` survives anywhere), the style-analyzer reads it first, and the style-patcher — which fought freshly-generated zh-anchored output chapter after chapter and imposed a per-chapter ack-gate throughput regression — is retired. All chapter-specific exec files are materialized by the compiler at Init from `disbinder_structure.json`, so no agent ever performs path substitution and the `$`-token grep is both necessary and sufficient. The `cp` and `grep` steps are split into two isolated `run_command` calls, so a copy failure is `PATTERN_FILE_COPY_FAILED` rather than a silent CLEAN on the highest-stakes gates, and `GREP_EXECUTION_ERROR` carries a three-way sub-code with a named recovery each. The agent-source list is a committed static manifest, not a runtime read-trace, so Phase-1 scans the right files. `drift_decisions.tsv` is Init-stubbed so chapter 1 returns no-matches rather than file-not-found. The Germanic negation token list, the multi-script truncation fallback, the expansion-lengthening omission adjustment, the n-ary formality ledger, the `morphological_with_mandatory_subject` French strategy, the `fixer_drain_K` constant, the Romance probe suite, the per-register probe selection, the content-word definition and coverage floor, and the producer of `ch{N}_relationship_shifts.json` are all now concretely specified rather than named. The deploy is gated all-or-nothing by Phase-1-clean agent source plus the zh-TW fixture, the committed en-de fixture (exercising the static vault, the gender-invariant repair gate with its negative case, the inflected-NEVER_USE HUMAN_REVIEW path, the left-boundary compound, the Sie/du shard conflict, and the serialized Germanic negation), and a PARTIAL/STUB-tier fixture validating graceful degradation — with Arabic diglossia, cross-chapter keigo, pro-drop honorific drift, the same-script stray cliff, and the minimal-Init fast path honestly declared as enforced-out-of-scope or open gaps rather than silently assumed working.
