## 0. North Star

**Produce HIGH-QUALITY literary translation using a Flash-class model as the workhorse.** Quality comes from **decomposition, context engineering, external-signal verification, robust structured output, and quality gates** — scaffold, not model size. Frontier/Pro tiers are spent only on a *justified, measured* hard tail: a one-time style-guide + gold-exemplar distillation; error annotation on sampled units; and escalation of below-threshold units after one repair.

Eleven standing cautions (the CC ledger, §10) govern every loop. They exist because the recurring failure mode is proposing work the repo cannot support — building on infrastructure that does not exist, mislabeling agent tiers, calling stochastic LLM work "deterministic," re-proposing protection the codebase already ships, fixing a symptom in the wrong agent, anchoring one agent to a draft snapshot another agent has already rewritten, treating Flash-scorer measurement noise as a gate signal, or **demanding the toolless orchestrator materialize, copy, or arithmetically rank files it has no primitive to touch.** In brief:

- **Tier demotion is the highest-stakes move.** "Flash-as-workhorse" is the destination, not a free move. The last deliberate decision put the literary agents on **Pro**. No Pro→Flash demotion of a literary-cognition agent may be made as a "mechanical refactor" or an unverified "scaffold compensates" claim — it requires a measured §5 benchmark showing scaffolded-Flash meets the Pro baseline on that agent's task.
- **No actuator, no determinism (CC8).** Structural-boundary chunking is desirable but unbuildable as scoped: workhorse agents have `bash: deny` and there is no tokenizer/parser/script. Admissible only behind a committed deterministic chunker/reassembler, or after whole-chapter overflow is proven on real fixtures.
- **Structured output is fragile (CC10).** Flash STATUS sentinels are the loop-exit signal but are not guaranteed well-formed. Hardening must make models reason before they verdict *without* split-write requirements no agent performs, must not assume STATUS is line 1, and must give the orchestrator a conservative fallback so malformation never reads as success.
- **The critique loop is Pro+Pro (CC11).** Any "Flash under-delivers here" diagnosis is a misdiagnosis. Accountability machinery (verbatim-excerpt anchors, self-certified apply-logs, "was-it-applied?" verifiers, rigid per-issue schemas, uncapped sub-loops) is rejected.
- **The glossary is read-only during Stage B (CC12/CC13/CC14).** Semantic-adequacy judgment is not Flash-reliable; window pressure is quantitatively false for the Pro/1M translators; and back-propagation crosses the one-way A→B boundary into a shared, unversioned, rollback-free artifact through a sub-Pro agent with no append primitive. All three are rejected.
- **Flash-tier mechanical prompts stay lean and tool-anchored (CC15).** Improving the Flash detectors is in-scope, but per-item census scaffolds, in-prompt contrastive examples, and fixer self-checks are net-negative.
- **Verify the feature is absent before adding it (CC16).** Special-content handling is *already implemented* in the four literary/critique files. Re-proposing it produces duplicate or conflicting constraint blocks.
- **Fix the symptom at the agent that owns it (CC17).** When a detector over-flags, the fix belongs in the detector's exclusion logic or a post-detector filter — never as a CoT triage block in a downstream actuator whose output is the published draft.
- **Do not forward stale draft excerpts across a mutation boundary (CC18).** Verbatim excerpts quoted from an early-Step draft cannot be used as binding anchors by any agent that runs after the omission/stray loops rewrite the draft. Cross-agent handoffs carry intent, not quote-located edit lists pinned to a vanished snapshot.
- **Do not gate on Flash-scorer noise (CC19).** The post-finalization scorer is a stochastic integer instrument; a 1-point swing is within its own variance. The 2-point regression threshold is a deliberate noise floor. No new gate, delta table, comparative re-run, or per-issue resolution audit may escalate inside that floor.
- **Best-of-N candidate selection is not in-pipeline buildable, and Flash cannot be its judge (CC20).** Generating N drafts and reranking them requires (a) the toolless orchestrator to materialize the winner at the canonical `draft/<f>` path — a write primitive it does not have; (b) genuine candidate diversity, which thin task-prompt addenda on a deeply-constrained Pro system prompt do not produce; and (c) a discriminating ranker, which the stochastic Flash 1–5 scorer is not (its single-dimension integer swing equals or exceeds any expected quality delta). N× Pro generation cost is real and dominant. Rejected.

## 1. Hard Constraints (every loop must preserve)

1. **Dual-harness pipeline.** Must run in antigravity (`agent.json`: `systemPromptSections`, `toolNames[]`, `systemPromptConfig`) AND opencode (markdown + frontmatter: `mode: subagent`, `permission:` map, optional `model:`). New agents/skills land in BOTH or neither.
2. **Harness parity is *semantic*, not byte-identical.** Intent stays identical; encodings legitimately differ in (a) tool-name prose (`run_command`/`grep_search` vs `bash`/`grep`), (b) config schema (`toolNames[]` vs `permission` booleans; `model:` exists only in opencode), (c) harness-only sections. A naive byte-diff is the wrong parity test.
3. **Valid EPUB out.** mimetype-first, stored (`-0`), no stray files; nav↔spine↔body reconciled; round-trip validated.
4. **Flash-class workhorse, evidence-gated tiers.** Stronger tiers only where a written justification AND a benchmark support them. A non-empty justification string alone is compliance theater.
5. **File-on-disk IPC; the orchestrator is a toolless LLM.** Agents communicate through artifacts, coordinated by the `lexis-orchestrator` *skill prose* — an LLM reading SKILL.md, not a config-driven runtime. The orchestrator reads STATUS sentinels out of artifact files, not return values, and **it cannot itself write, copy, move, rename, or arithmetically reduce files**: every byte on disk is produced by an invoked agent. Any control-flow step that requires materializing a chosen file at a canonical path, or selecting among on-disk candidates and promoting one, is not orchestrator-executable without a new agent invocation (which must be costed) or a committed actuator (constraint 7 / CC8).
6. **Prose generation stays free-form; structure is isolated.** Forcing JSON from Flash degrades quality and malforms (repo-confirmed reversion to markdown; `lexical-management/SKILL.md`: "Markdown format is required over raw JSON to avoid Flash-model parse failures that would be indistinguishable from agent failure"). Translation/critique outputs are prose; machine-readable signals are markdown `STATUS:`/`SCORE_VERDICT:` sentinels plus loosely-parsed report bodies — never strict JSON *out of a Flash agent*. (`master_glossary.json` is written by `glossary-manager`, a default-tier agent producing strict JSON via destructive full-rewrite — a known fragility, not license to add new Flash-emitted JSON artifacts or write paths into it.)
7. **No net-new build/CI substrate without paying its cost.** The repo has ZERO tooling. Any generator/manifest/CI gate must justify its maintenance surface against the drift it prevents AND verify the keys it writes are *consumed* by the target harness.
8. **No actuator, no determinism (CC8).** Any step labeled "deterministic" (chunk splitting, token budgeting, length gates, verbatim-marker copy, byte-exact reassembly, set-equality coverage, grep-based loop-exit, occurrence-count sorting, draft-vs-final string diffing, file-copy/promotion, multi-file score arithmetic) is, absent a committed script and the tool grant to run it, executed by a stochastic LLM. Either add the actuator (paying constraint 7) or design around LLM fallibility.
9. **Stage A → Stage B is a one-way boundary.** Stage B reads Stage-A artifacts; it never writes them. No Stage-B agent gains a write path into `master_glossary.json`, the lexicons, summaries, `challenges.md`, or any other Stage-A output (CC14). The glossary is built once, before translation, and is immutable for the run.
10. **Don't re-add what's already there (CC16).** Before proposing an agent instruction, confirm the live agent file does not already contain equivalent or stronger logic. Duplicate constraint blocks create ordering ambiguity and instruction conflict.
11. **Fix the symptom where it originates (CC17).** A downstream agent must not be made to second-guess and silently override the artifact it was handed; that hides the defect from the orchestrator and creates a non-auditable failure mode. Repair upstream (the producer's filter logic) or at a gated intermediate, never inside a terminal actuator whose output is a published artifact.
12. **No cross-agent excerpt anchoring across a mutation boundary (CC18).** The draft is rewritten in place by the omission and stray loops within Stage B; any verbatim excerpt one agent quotes from an early-Step draft is stale before a later agent reads it. Handoffs between Stage-B agents pass intent/dimensions/free-form prose, never quote-located edit lists pinned to a draft snapshot that no longer exists at the consumer's invocation time.
13. **Respect the scorer noise floor (CC19).** The post-finalization scorer is a stochastic Flash 1–5 instrument. Its `SCORE_VERDICT:` and the 2-point regression threshold are the only sanctioned consumers of its output. No gate may escalate on a sub-2-point delta, compare a final scorecard against a pre-mutation draft scorecard, or add a per-issue resolution/regression verdict.
14. **One draft path, one scorecard path; no candidate proliferation (CC20).** There is a single canonical `draft/<filename>` and a single canonical scorecard per chapter. No control flow may produce sidecar candidate drafts (`.c1`/`.c2`/`.cand_b`), sidecar scorecards, or require the orchestrator to choose among them and copy a winner forward. Best-of-N selection is not orchestrator-executable (constraint 5) and is not a quality win on this scorer (§4.1, CC20).

## 4. Redesign Directions

**4.1 First-pass quality without multi-draft reranking (RE-SCOPED, CC20).** The biggest mid-tier first-pass lever is **the quality of the single draft's prompt and injected context**, not generating several drafts and picking one. Best-of-N + QE reranking is a valid technique in MT literature, but its in-pipeline instantiation here is rejected (§4.16, CC20): the toolless orchestrator cannot promote a winning candidate to `draft/<f>` (constraint 5), thin task-prompt addenda on the deeply-constrained Pro system prompt do not yield discriminable candidates, and the stochastic Flash 1–5 scorer cannot reliably rank near-identical drafts (its single-dimension integer swing ≥ any plausible quality delta). The retained, in-scope levers are: distill a frontier-authored style guide + 3–5 gold exemplars once and inject them into every translator call (§4.6); the book-bible context bundle (§4.3); and Flash-only prompt enrichment (§4.4) where the translator is later demoted. An *external* QE estimator, if one ever exists, is consumed only as a threshold at the §5 gate / escalation router (§4.11) — never as an in-Stage-B reranker emitting forwarded excerpts.

**4.2 Decomposition (translator-brain vs editor-brain)** — the *aspirational* unit is a structural-boundary chunk enabling single-objective passes (draft → source-anchored accuracy/omission → target-only fluency/voice → proofread). **BLOCKED by CC8:** sub-chapter chunking manufactures N seams per chapter and needs deterministic split + reassembly no agent can do reliably. **Admissible path:** (a) commit a tag-aware, CJK-safe chunker/reassembler *script* (pays constraint 7), OR (b) prove whole-chapter overflow on real fixtures. Until then, achieve **single-objective passes at whole-file granularity** (separate accuracy, fluency, proofread passes over whole `draft/<f>`) without seams. Prefer (b)-then-whole-file now; defer true chunking to a loop that builds the actuator.

**4.3 Context / memory (the book bible)** — one persistent, injected guideline = {locked glossary, tone/style/register sheet, rolling bilingual plot+character-state summary, per-character voice cards}. DelTA-style: freeze proper nouns on first occurrence; refresh summary every ~20 segments. Terminology: translate-then-revise + post-hoc check/replace; inject inflected target forms, not lemmas; proper-noun/neologism = locked (deviation = hard fail); idiom/slang = dynamic-equivalence-permitted (the `glossary-manager` `usage_notes` already authorize this downstream). **The glossary is read-only during Stage B (CC14):** memory that must evolve per chapter (plot state, newly-clarified register, continuity facts) lives in the rolling bilingual summary carried forward (§4.8), NOT in mutations of `master_glossary.json`.

*Glossary delivery (RE-SCOPED, CC13).* At the Pro/1M translators the full `master_glossary.json` is ~4–5% of the window, so it is **not the bottleneck** and a per-chapter filter is unjustified today. The previously-proposed scoping schemes are rejected because: (i) a filter agent must itself read the full glossary + full chapter, so its input cost equals what it claims to remove; (ii) `sections` is *backward provenance*, so filtering on it strips recurring proper-noun/neologism anchors from exactly the late chapters that need them; (iii) `local-lexicographer` extracts only terms *new* to a chapter, so chapter-lexicon-presence filtering silently omits established names; (iv) a Flash filter emitting the full glossary JSON reintroduces the banned malformation mode (constraint 6); (v) `usage_notes`-bearing idiom/slang entries can be silently dropped; (vi) writing the shared, unversioned, rollback-free glossary lets one bad Flash inference corrupt every downstream chapter. **Sanctioned cheap wins only:** frequency/recency *ordering* of an already-complete glossary and a small locked-core in the system prompt — and even these require a real actuator to compute occurrence counts deterministically (CC8); absent one, leave delivery as the whole-glossary read it is today.

**4.4 Flash-tier prompt rewrites (Flash agents only, bounded by CC15).** Legitimate levers for Flash under-delivery (W17): in-prompt contrastive examples and MAPS-style self-generated keywords/topic/demo before translating — applied **only to the literary Flash work and never to the Pro `native-critique`/`final-translator` pair** (schema pressure fragments multi-clause Pro diagnoses, CC11). **For the mechanical Flash agents (`omission-detector`, `stray-phrase-detector`, `stray-phrase-fixer`, `translation-scorer`), CC15 bounds what is admissible:** prompt changes must (a) preserve the `stray-phrase-detector` grep/regex zero-hit fast-path; (b) not add static contrastive-example tokens that compete with chapter text in the in-loop context budget; (c) not introduce self-reported counts inside the scratchpad that create a premature-STATUS contamination vector; (d) not rename `omission-detector` field labels without simultaneously updating `primary-translator`'s reader; (e) not add fixer self-checks or inline annotation markers into `draft/<f>`. **CC17 adds a placement rule:** a quality gap caused by *wrong inputs* is fixed at the producing agent, never by adding a triage/override pass to a consuming actuator (see §4.14). No such change has cleared this bar; the current mechanical-agent prompts stand.

**4.5 Reflection / critique loops** — ground every refinement in an external signal (back-translation divergence, xCOMET-QE spans, error-typed Estimate), never free self-critique. Cap 1–2 rounds; accept only if QE improves else revert; log self-estimate vs QE. Emit per-chapter `diagnostics.json`.

**4.6 Model-tier execution** — *see §2.* Default = ba86672 baseline. Frontier spent once (style guide + gold exemplars) and on the measured hard tail. opencode pins via `model:` (provider-prefixed, no `timeout_mins`); antigravity via AGENTS.md operator table. No Pro→Flash demotion of a literary agent without a §5 benchmark.

**4.7 Critique grounding, special content, and adequacy (RESOLVED).** Two real gaps existed and are both closed; no further machinery is admissible without a measured delta.

- **Adequacy grounding (W7).** `native-critique` reads `original/<f>` and is instructed to critique adequacy/fidelity (mistranslation, omission, added content, register drift) against the source as well as target-side fluency. No new sentinel, schema, apply-log, or verifier agent.
- **Special-content fidelity (W12/W23 — LIVE).** Non-prose structure (footnotes, tables, verse/poetry, ruby/furigana, image captions) is protected end-to-end through the existing prose pipeline without a new agent or sentinel:
  - **Inventory (Stage A):** `narrative-summarizer` scans each section and, when non-prose structure exists, appends a `## Special Content` section of `SC-N` entries (`Type` ∈ {footnote, table, verse, ruby, caption}; `Location` excerpt; per-type `Translation Strategy`) to `challenges.md`. If none are found it omits the section — its absence is the "apply normal critique" signal.
  - **Critique exemption:** `native-critique` reads `challenges.md` and, per its **constraint 4 (MANDATORY)**, treats each SC-N element's structural features as inviolable (verse line breaks; table cell/header/row ordering; footnote marker/note separation; ruby parenthetical glosses; image-proximate caption brevity). The damaging suggestion is blocked **at source** so it never enters the critique file.
  - **Finalization override:** `final-translator` carries a **step 5 (MANDATORY) Special Content Hard Constraint**: before applying a critique suggestion, it reads the SC-N entries and, if a suggestion touches an SC-N passage and conflicts with that entry's Translation Strategy, it **discards the suggestion silently** and preserves the draft's rendering. The glossary-priority rule (step 3) is unaffected. It inherits the override pattern's one limitation: matching a free-text critique suggestion to an SC-N passage is a **fuzzy cross-reference**, so effectiveness depends on the quality/specificity of the SC-N `Location` excerpt.
- **REJECTED, do not re-add (CC16):** a positive "apply the SC-N strategy from scratch" step in `final-translator`; any duplicate SC-aware block under new headings in any of the four files.
- **Keep the critique→finalize pair single-pass Pro+Pro (CC11).** `final-translator` consumes `critique/<f>.critique.md` as free-form prose and produces `final/<f>` under its "output ONLY the final translated text" contract. **Explicitly REJECTED:** typed-issue checklists, verbatim-excerpt anchors, self-certified apply-logs, a "was-it-applied?" verifier, integer `ISSUE_COUNT` sentinels, uncapped re-passes.
- **Future grounding (gated):** if a real QE/back-translation signal later exists (§4.11), refinement may iterate cap 1–2 accepting only when QE improves (§4.5) — grounded in an external estimator, not a self-authored log, and **not via forwarded draft excerpts (CC18)**.

**4.8 Cross-chapter consistency & evolving memory** — post-finalization consistency-auditor over `final/` + glossary (name/tone/continuity drift; alignment/null-ratio) gating packaging; **a rolling bilingual summary + locked glossary carried forward is the sanctioned home for per-chapter memory that must evolve** (plot state, character-state, register clarified only in rendered prose). This is the principled answer to "register/idiom discoveries should propagate" (W22): continuity travels in the forward-carried summary — *additive working memory* the next chapter's translators read alongside the immutable glossary — NOT a write-back into the shared glossary (CC14). The summary is per-run scratch context, not a shared cross-chapter artifact whose corruption poisons all downstream chapters.

**4.9 EPUB fidelity** — deterministic OPF/nav mapping from precomputed values + `xmllint` + round-trip structural validation; reconcile nav labels vs final headings before zip; staged packaging with an explicit file allowlist (no `*` glob). (Requires the actuator per CC8/§1.8 — packaging is Flash with no parser today.) Special-content *structural* fidelity inside chapter bodies is protected upstream by the SC-N layer (§4.7); EPUB-level fidelity here remains about container/OPF/nav integrity.

**4.10 Robustness / structured output** — free-form prose generation; structure isolated to markdown `STATUS:`/`SCORE_VERDICT:` sentinels plus loosely-parsed report bodies (never strict JSON from Flash; no new Flash-emitted JSON artifacts). Tolerant status parsing: scan the whole artifact for the sentinel line (NOT guaranteed to be line 1 for `STATUS:`; `SCORE_VERDICT:` is mandated as the last line); classify failure type (transient→fallback, permanent→escalate); see §4.13 for the conservative-default fallback.

**4.11 Quality-gated escalation router + the out-of-loop scorer (the ONLY sanctioned home for a score signal).** Use QE + back-translation divergence to route below-threshold units (after one repair) to a stronger model, keeping Flash on the easy ~90%; an asymmetric setup where a stronger model annotates errors on sampled units breaks same-model self-bias. **A scorer is admissible ONLY as an out-of-loop, post-finalization estimator** — which is exactly what is LIVE: `translation-scorer` (Flash) reads the *stabilized* `final/<f>` and writes `notes/<f>.final.score.md` ending in `SCORE_VERDICT:` (last line; PASS requires Adequacy ≥ 3), consumed at the §5 gate as a threshold. This is the *only* sanctioned home for semantic-accuracy validation and for any "translation scorer" idea (CC12, W25/W26/W27).

**It is NOT** a new in-Stage-B Flash agent that emits a scorecard whose verbatim excerpts are forwarded to the Pro critique/finalize stages — rejected outright (CC18): a scorer running on an early-Step draft produces excerpts the omission and stray loops mutate away before `native-critique` or `final-translator` run. The Pro stages already ground adequacy against `original/<f>` (§4.7, facts 9–10). **It is also NOT** a comparative draft-vs-final regression detector (CC19, §4.15), **and it is NOT a best-of-N candidate reranker (CC20, §4.16)** — it is a single-invocation, single-path, absolute estimator, never a relative ranker across drafts it is not calibrated to discriminate. If a numeric score is consumed in-pipeline it must (a) be computed on the *stabilized* artifact, (b) be consumed as a *threshold at the §5 gate / escalation router*, not as forwarded excerpts or a candidate ranking, and (c) be read against its own deliberate noise floor — never escalated on a sub-2-point swing.

**4.12 Parallelism** — parallelize independent Phase-1 init + Stage-A; N-chapter lookahead using glossary snapshots; sequential glossary consolidation. Stage-A parallelism remains safe precisely because the glossary stops mutating once Stage A completes — preserving the one-way boundary (CC14) keeps the snapshot semantics clean. (SC-N inventory is a Stage-A `narrative-summarizer` output, so it parallelizes cleanly under the same barrier.)

**4.13 Structured-output robustness — STATUS hardening + orchestrator fallback.** Two paired-edit changes; no new agents, no new tooling, no split-write behavior.

*(a) Detector-side: conditional scratchpad on the ISSUES path only.* In `stray-phrase-detector` (opencode `.md` + antigravity `agent.json`), require the `<scratchpad>` reasoning **only when stray candidates are found**. The **zero-hit grep/regex fast path is explicitly preserved**: no source-script hits → emit `STATUS: CLEAN` directly with **no scratchpad** (CC15). This mirrors omission-detector's reason-then-verdict shape and does NOT introduce any "write only the post-scratchpad portion" requirement. Because the scratchpad lands in the artifact, the orchestrator locates STATUS by scanning the file, not by reading line 1 (§4.10).

*(b) Orchestrator-side: conservative-default fallback, sharing the existing 3-iteration cap.* Both `lexis-orchestrator/SKILL.md` copies already contain `## Error Handling` with the shared cap. Add:

```
- **Malformed STATUS** (Steps 4.1 and 4.2): If you read the report file and
  cannot locate a `STATUS:` line anywhere in it, treat it as the conservative
  error value: `STATUS: INCOMPLETE` for omission reports, `STATUS: ISSUES_FOUND`
  for stray reports. Never treat a missing or unparseable STATUS as clean
  passage. Log the malformation in diagnostics, then re-invoke the detector.
  This re-invocation counts as one normal iteration of the SAME loop and is
  charged against the existing 3-iteration cap for that loop — it does NOT get
  a separate retry budget and does NOT reset the counter. If the cap is reached
  with the status still malformed, pause and request human intervention.
```

This preserves the CLEAN fast-path, uses the existing insertion point in both harnesses, and shares the 3-iteration cap so malformed-STATUS retries cannot starve real detection. The rejected variant (mandatory unconditional scratchpad + selective partial-write + grep-first orchestrator protocol) is NOT adopted (CC10).

**4.14 Stray-phrase detection/fix division of labor (CC17 — placement is load-bearing).** The validation loop is two agents with a strict contract: `stray-phrase-detector` (Flash, grep fast-path + exclusion rule for proper nouns / technical terms / intentionally-identical code) decides *what is a stray phrase*; `stray-phrase-fixer` (Flash) *acts on the report it is handed* and its **output IS `draft/<filename>`** ("Output ONLY the complete, updated translated text… Do not include commentary or markdown blocks"), with **no STATUS sentinel**. The fixer already reads `master_glossary.json`, `challenges.md`, and the source, and is already instructed to use the glossary for lexical consistency.

Consequently, "add a three-way classify-then-translate triage scratchpad with contrastive exemplars to the fixer" is **REJECTED (CC17)** for four independent reasons: (1) **Wrong agent** — if proper nouns reach the fixer it is a *detector* false-positive; the fix is the detector's exclusion logic or a gated post-detector filter, not a second filter downstream that must contradict the report it was told to act on. (2) **Output-contract violation** — the fixer's stream IS the draft; a `<scratchpad>` fence risks leaking XML-tagged reasoning into `draft/<f>` (Flash leaks fences at non-trivial rates; no downstream step strips them; it reaches the published EPUB). The omission-detector analogy fails: that scratchpad precedes a STATUS sentinel in a *separate report file*; the fixer has neither. (3) **Silent, unauditable regression** — a "KEEP/INTENTIONAL" branch lets Flash suppress a detector finding with no artifact and no orchestrator signal; a genuine untranslated miss misclassified as KEEP exits CLEAN with no recovery. (4) **Loop-coherence defect** — if the fixer instead leaves a KEEP phrase unchanged, the detector re-flags it and the loop spins to the 3-cap into a false human-intervention failure; there is no KEEP back-channel. **Sanctioned path for W24:** tighten the detector's exclusion rule, or insert a gated post-detector filter that *rewrites the report* (an auditable artifact the orchestrator sees) before the fixer runs — never give the terminal fixer override authority over its own input.

**4.15 In-pipeline / comparative scoring — why it can only live out-of-loop at the gate (CC18 + CC19).** Two distinct scorer-placement families are rejected on structural, not cosmetic, grounds.

*(i) In-Stage-B scorer forwarding excerpts to a Pro consumer (CC18).* Stage B mutates `draft/<filename>` in place — the omission loop reruns `primary-translator` up to 3 times and the stray-phrase-fixer loop edits the draft up to 3 times, up to six rewrite passes, **between** any Step-4.0 scoring pass and the moment `native-critique` (4.3) or `final-translator` (4.4) reads the draft. A scorecard's ≤20-word verbatim excerpts are anchors into the pre-mutation snapshot; by consumption time they may be reworded or removed, so a "guarantee every listed issue is addressed by Location excerpt" instruction resolves against vanished text — silent skip, phantom-passage chasing, or a halt. Compounding defects: routing Adequacy findings to source-reading Pro recipients is *redundant* (they already read `original/<f>`, §4.7); an "Adequacy = mandatory" directive collides with the MANDATORY SC-N hard constraint (step 5) with no tie-breaker; and it is a four-file paired edit carrying real drift for a benefit the Pro model already achieves.

*(ii) Comparative draft-vs-final regression detector (CC19).* The post-finalization scorer is LIVE and out-of-loop by design: it reads the *stabilized* `final/<f>` only. Every variant that would make it **also read `draft/<f>` and emit a regression judgment** is rejected:
- A draft-vs-final delta table or 1-point Adequacy-drop escalation **gates on the scorer's own noise**. The scorer is a stochastic integer 1–5 Flash instrument; the same finalized text can score Adequacy 4 or 3 on consecutive runs. The orchestrator's `## Error Handling` already encodes the deliberate floor — "do not gate-halt on a 1-point drop." A 1-point gate manufactures false-alarm human interrupts on virtually every multi-chapter book.
- The comparison itself is **invalid**: any draft scorecard would have been generated before the omission/stray/critique passes mutated the text, so a draft-vs-final delta conflates legitimate pipeline improvement with regression — it is not a clean A/B.
- A `REGRESSION_VERDICT:` sentinel placed before `SCORE_VERDICT:` **breaks the "last line, no trailing text" invariant** and asks Flash to perform three-document Major/Minor/None judgment — harder and noisier than the numeric delta it replaces.
- A per-issue "Issue Resolution Audit" against the Step-4.0 Critical Issues list is **CC18 in another costume**: the issues were quoted from the pre-loop draft, so the audit searches `final/<f>` for excerpts `final-translator` deliberately revised.

**Disposition:** the scorer stays exactly as it is — out-of-loop, final-only, single-invocation, single-path, `SCORE_VERDICT`-terminated, consumed at the §5 gate against its 2-point floor. Phase 5 reads only the final scorecard; it does not read or diff a draft scorecard.

**4.16 Best-of-N candidate generation + scorer reranking — why it cannot live in this pipeline (CC20).** Generating N drafts at Step 4.0 and reranking them with the `translation-scorer` is a recurring proposal (best-of-2 stratified, best-of-3 emphasis-differentiated, orchestrator-driven multi-draft). All variants are rejected on four independent, compounding grounds; none is cosmetic.

- **(a) Winner promotion is not orchestrator-executable (constraint 5 / CC8).** Whatever the candidates are named (`.cand_a`/`.cand_b`, `.c1`/`.c2`/`.c3`), the selected candidate must end up at the canonical `draft/<filename>` for every downstream agent to read it. The orchestrator is a toolless LLM with **no write/copy/move primitive**; the only CC8-compliant way to materialize the winner at the canonical path is to invoke a Pro agent a further time to re-emit it — an unbudgeted extra Pro call that invalidates the cost arithmetic and is itself the "implicit actuator" the proposals claim to avoid. There is no admissible copy step.
- **(b) Thin addenda do not produce discriminable candidates.** `primary-translator`'s system prompt already mandates completeness, naturalization, and stylistic fidelity *simultaneously and at depth*. A one-sentence task-prompt addendum ("emphasize completeness" / "domesticating vs source-structure") narrows an already multi-objective instruction; a Pro model reading a ~2000-token constrained system prompt will not reliably honor a thin nudge over its body directives (and a "source-structure" brief directly contradicts the Dynamic Equivalence and Dialogue Naturalization rules). The candidates converge toward an undefined blend, so reranking measures near-identical drafts.
- **(c) The Flash scorer cannot rank them (CC19 applies to selection too).** The scorer is a stochastic integer 1–5 absolute estimator, explicitly "do not gate on a 1-point drop." A single-dimension integer flip shifts Overall by 0.20–0.45 — equal to or larger than any tie-break threshold and larger than the expected true quality delta between near-identical candidates. Selection therefore tracks *which run got the more lenient scorer pass*, not which draft is better; re-running the scorer on the same text can flip the winner. It is calibrated as an absolute gate, not a relative ranker, and emphasis-differentiated candidates each score high on their emphasized axis and low on the others, so the weighted formula systematically rewards the "balance" candidate regardless of the chapter's actual failure mode.
- **(d) Cost is N× the dominant per-chapter driver.** `primary-translator` is the single most expensive call; N drafts is an N× Pro increase per chapter (20–30× over a book), framed in the proposals as "essentially free." The claimed downstream saving (fewer omission-loop iterations) has no mechanism — omissions come from context-length pressure near chapter end, identical across candidates sharing one model and budget.
- **Compounding breakages:** candidate sidecars persist in `draft/` and are matched by `primary-translator`'s Step-4.1 filename-pattern reads (contradicting "zero downstream interference"); a winning candidate's scorecard at a non-canonical path silently breaks Step 4.5 / Phase 5 which read one fixed path; the antigravity orchestrator has no defined mechanism to pass distinct per-invocation output paths; and the dual-harness sync burden is non-trivial for negative expected value.

**Disposition:** no in-pipeline best-of-N. The sanctioned first-pass quality levers are prompt/context quality (§4.1, §4.3, §4.4) and frontier style-guide + gold-exemplar distillation (§4.6). A relative selection mechanism becomes admissible only behind (i) a committed deterministic actuator that promotes the winner and does the score arithmetic (CC8/constraint 7), AND (ii) a real external QE ranker calibrated for cross-candidate comparison — not the Flash absolute scorer (CC19).

## 5. Automated Quality Gates

Layered acceptance gate, in order: (1) **cheap pre-screen** — non-empty; length-ratio as a *gross* breakage guard only (`<~10%` = truncation is the only defensible threshold; per-paragraph ratios swing 1.5–3× under dynamic equivalence); lang-ID; copied-source detection. (2) **correctness** via QE/GEMBA-MQM (drop Locale, pin model version, reason in human-perceptible deltas). (3) **literary quality** via the LIVE post-finalization `translation-scorer` (Flash, out-of-loop) and a LiTransProQA-style yes/no/maybe judge (Tone & Voice + General Equivalence weighted highest); `SCORE_VERDICT:` on the last line, PASS requires Adequacy ≥ 3. **Never tune the generator against COMET/BLEU** — they reward literal translationese; BLEU/chrF only as breakage guards. Reserve periodic human MQM/ESA for calibration.

This gate is the **only legitimate consumer of a translation score** (CC18/CC19/CC20): the score is a threshold computed on the *stabilized* `final/<f>`, never an excerpt brief forwarded into Stage B, never a draft-vs-final delta, and never a candidate ranking. **Honor the noise floor (CC19):** gate-halt only on `SCORE_VERDICT: FAIL` / Adequacy < 3 / a ≥2-point regression; never on a 1-point swing; Phase 5 reads only the final scorecard. The gate is also the evidence source for §0's tier-demotion rule: a Flash agent may replace a Pro agent only if its gate scores meet the Pro baseline on held-out chapters. **Caveat (CC8):** any "deterministic pre-screen" step still needs a real actuator; absent one the string pre-screen is itself LLM-in-context and unreliable for arithmetic/length math.

## 6. Pipeline Architecture (current, for reference)

- **Phase 0 Disbind:** `ebook-disbinder` (Flash) shells `unzip` `source.epub` → `original/` (whole standalone XHTML docs; no parsing).
- **Phase 1 Global init (once):** `toc-generator` → `notes/contents.json` ({index, filename, title}); `style-analyzer` → `notes/style_guide.md`; `metadata-generator` (Pro) → `notes/metadata.json` (source/target lang, audience, contrastive guidance).
- **Stage A (per chapter, ALL chapters before any Stage B):** `narrative-summarizer` (`bash:deny`) → `notes/<f>.summary.txt` + `notes/<f>.challenges.md` (**incl. an appended `## Special Content` SC-N inventory when non-prose structure exists; section omitted otherwise**); `local-lexicographer` → `notes/<f>.lexicon.md` (terms *new* to the chapter only); `glossary-manager` → `notes/master_glossary.json` (strict JSON via destructive full-rewrite; `sections` = backward provenance). **After Stage A completes, `master_glossary.json` and all `challenges.md` files are frozen for the run (CC14).**
- **Stage B (per chapter, sequential, whole-file unit):**
  - **Draft loop ≤3:** `primary-translator` **(Pro/1M, `bash:deny`)** → `draft/<f>` (one draft, one canonical path — no candidate sidecars, CC20); `omission-detector` (Flash, `bash:deny`, reads source+draft only — scratchpad-then-`STATUS:` → `notes/<f>.omission_report.md`, additive re-insert until `STATUS: COMPLETE`). **The draft is mutated in place across these iterations (CC18).**
  - **Validation loop ≤3:** `stray-phrase-detector` (Flash, grep/regex zero-hit fast-path, exclusion rule for proper nouns/technical/code → `notes/<f>.stray_report.md`); if not `STATUS: CLEAN`, `stray-phrase-fixer` (Flash, reads glossary + challenges + source, patches in place, emits full updated `draft/<f>`, **no STATUS sentinel**). **The draft is further mutated in place here (CC18).**
  - **Refinement:** `native-critique` **(Pro)**, reads `draft/<f>` (current, post-mutation) + `metadata.json` + `original/<f>` (adequacy) **+ `challenges.md` (SC-N exemption, constraint 4)** → `critique/<f>.critique.md`.
  - **Finalization:** `final-translator` **(Pro/1M)**, reads `original/<f>` + glossary read-only + `challenges.md` + the current `draft/<f>` + critique; single-pass free-form-critique consumer; glossary-priority (step 3) + **SC-N hard constraint (step 5)**; single output → `final/<f>`.
  - **Scoring (out-of-loop):** `translation-scorer` (Flash) reads the stabilized `final/<f>` → `notes/<f>.final.score.md` ending in `SCORE_VERDICT:` (last line; PASS ⇒ Adequacy ≥ 3). One invocation, one canonical path. It does NOT read `draft/<f>` (CC19), does NOT rank candidates (CC20), and does NOT forward excerpts into any Stage-B agent (CC18).
  - **No Stage-B agent writes back to any `notes/` Stage-A artifact (CC14). No Stage-B agent forwards verbatim draft excerpts pinned to an earlier draft snapshot (CC18). No control flow produces or selects among candidate drafts (CC20).**
- **Packaging (after user confirm + §5 gate):** `ebook-packager` (Flash) mirrors assets, localizes OPF/nav, zips `translated_book.epub` mimetype-first stored.

Skills: `lexis-orchestrator`, `epub-handling`, `lexical-management`, `narrative-translation`, `translation-validation`.

## 7. Orchestrator Control Flow & Thresholds

`lexis-orchestrator` SKILL.md (prose, LLM-driven, toolless) sequences: Phase 0 → Phase 1 → Stage A (barrier: all chapters complete) → Stage B per chapter → out-of-loop scoring → Phase 5 gate → user-confirm → Packaging. The Stage-A barrier is also the **freeze point** — nothing after it mutates `master_glossary.json` or `challenges.md` (CC14). The orchestrator has **no file primitive of its own**: it cannot copy, promote, or arithmetically reduce files; every artifact is written by an invoked agent (constraint 5). Any control step that would require choosing among on-disk files and copying one forward is not expressible (CC20).

**Current thresholds are fixed counts:** draft loop ≤3 on `STATUS: COMPLETE`; validation loop ≤3 on `STATUS: CLEAN` (the fixer emits no sentinel — the loop re-checks via the *detector*, so any fixer behavior that fails to mutate a flagged phrase spins the loop to the cap, CC17); **critique→finalize is single-pass with NO loop cap on steps 4.3/4.4** (intentional — every proposed re-pass mechanism so far was uncapped and self-certified, CC11). The critique/finalize pair enforces SC-N structural protection inline (§4.7) without adding any loop.

**The draft is the live mutating artifact through Steps 4.1–4.2 (CC18).** Any signal an agent emits about the draft is valid only at that agent's own invocation; the orchestrator must never carry a downstream agent forward on verbatim excerpts captured at an earlier step.

**Scoring & the Phase-5 gate (CC19/CC20).** `translation-scorer` runs once on the stabilized `final/<f>`; the orchestrator consumes the single `notes/<f>.final.score.md` at Phase 5 by reading its terminal `SCORE_VERDICT:` line. **Phase 5 reads ONLY the final scorecard** — there is no draft scorecard, no draft-vs-final delta, no comparative re-run, no per-issue resolution audit, and no candidate scorecard set to rank. Gate-halt fires only on `SCORE_VERDICT: FAIL` / Adequacy < 3 / a deliberate ≥2-point regression; a 1-point Adequacy swing is absorbed as scorer noise. If a numeric score is ever recomputed in-pipeline it is computed on the stabilized artifact, never reused from a pre-mutation snapshot (§4.11/§4.15).

**STATUS reads are tolerant:** scan the whole report file for a `STATUS:` line and, on absence/unparseability, apply the conservative default (`INCOMPLETE`/`ISSUES_FOUND`) and re-invoke within the SAME loop's existing 3-iteration cap (§4.13). For `SCORE_VERDICT:`, read the last line; on absence apply the conservative default (treat as below threshold) and re-invoke the scorer once.

**Target thresholds:** replace count-only exits with **scored exits** — draft/refine loops accept only when the §5 gate passes OR `max_iter=f(tokens,error_count)` is hit (cap 1–2 for refinement, accept-only-if-QE-improves-else-revert); packaging **blocked** until the chapter passes the §5 acceptance gate and the cross-chapter consistency-auditor clears. Any *future* critique-iteration must arrive with an explicit cap AND an external grounding signal (§4.11 prerequisite), grounded on the current draft, not a stale excerpt set (CC18). Failure classification routes transient faults to fallback/retry and permanent faults (refusal, overflow) to escalation per §4.11. All thresholds, per-loop signals, score verdicts, and malformation events land in `diagnostics.json`.

## 8. Harness-Parity Notes

- Parity is **semantic paired-edit discipline**, not byte-equality (constraint 2). The §2 model-tier change is canonical: identical *intent* (ba86672 tiers), legitimately divergent *encoding* — opencode gets a provider-prefixed `model:` line; antigravity gets an AGENTS.md operator table.
- **The SC-N change is a verified four-file paired edit (LIVE):** `native-critique` (opencode `.md` constraint 4 + input-source line; antigravity `agent.json` `systemPromptSections[].content`) and `final-translator` (opencode `.md` step 5; antigravity `agent.json`). Any further SC-N refinement (e.g. richer `Location` excerpts) is also a two-file paired edit and must not desync the critique reader from the finalize override.

The scorer is single-invocation/single-path; no candidate-ranking variant is admissible (CC20).

Cost weighed against demonstrated (not asserted) benefit before admissible. A detector-side W24 fix is a 2-file edit; a triage-in-fixer "fix" is rejected on correctness grounds (CC17).
- **Any new in-Stage-B agent is a two-file create plus orchestrator wiring in both `lexis-orchestrator/SKILL.md` copies — and is rejected on correctness before cost if it forwards stale excerpts (CC18), gates on scorer noise (CC19), or requires the toolless orchestrator to promote a chosen file (CC20).** A multi-draft / candidate-generation change additionally has no antigravity-harness mechanism for distinct per-invocation output paths.

A write-back proposal additionally fails CC14 outright.
- Verified legitimate divergences mean any single-source generator must carry real harness-specific translation logic — relocating drift into the generator and adding a build dependency to a zero-tooling repo. Prior loops rejected the generator+CI approach.
- **Lighter mechanisms (future loops):** (a) a paired-edit checklist convention; (b) a *targeted* checker over only safely-comparable surface (agent-set membership, descriptions, presence-of-`model`-field, tier-map agreement, sentinel vocabulary incl. `SCORE_VERDICT:`-last-line, read-scope of `native-critique`, glossary-reader set, SC-N constraint presence, detector exclusion-rule presence, scorer final-only read-scope, single-draft-path invariant), excluding prose bodies and schema-divergent fields; (c) an advisory normalized-prompt diff stripping enumerated harness-specific tokens. Any checker must verify the fields it checks are actually consumed.

## 9. Loop Operating Rules

1. Each loop proposes a concrete change, names the harness files it touches in BOTH encodings, and states the parity-preservation step.
2. **Verify against the repo before proposing.** The recurring failure mode is building on infrastructure that does not exist (manifests, tier fields, QE scores, chunk/block-id grids, orchestrator grep access, an orchestrator file-write/copy primitive, a `glossary-manager` append primitive, a fixer STATUS sentinel, a draft scorecard at Phase 5, candidate-draft sidecars, a stable draft snapshot between Stage-B steps), writing config keys the harness ignores (`timeout_mins` in opencode), misreading an agent's tier (native-critique/final-translator are Pro; the literary translators have ~1M windows), misreading execution order (Stage A finishes for ALL chapters before any Stage B; the draft mutates between scoring and critique/finalize; the scorer runs final-only and once), proposing a new agent for a job an existing agent already does, misreading the data model (`sections` is backward provenance; `local-lexicographer` extracts only chapter-new terms), mislabeling a default-tier agent as Flash, re-proposing a shipped feature (the SC-N layer; the out-of-loop scorer), fixing a symptom at the wrong agent (CC17), anchoring a downstream agent to stale excerpts (CC18), gating on a sub-2-point Flash-scorer swing (CC19), or **proposing best-of-N/multi-draft selection the toolless orchestrator cannot promote and the Flash scorer cannot rank (CC20)**. Confirm field existence AND consumption AND actuator availability AND the agent's actual model pin/window AND that the claimed gap is not already covered AND that the agent you edit owns the defect AND that any excerpt you forward is still valid at the consumer's invocation AND that any score delta clears the noise floor AND that any chosen file can actually be materialized at its canonical path AND the true affected-file set; provider-prefix all opencode model IDs; never assume STATUS is the leading line; never break the `SCORE_VERDICT:`-last-line invariant.
3. Prefer scaffold over model upgrades; any tier *change* (esp. Pro→Flash on a literary agent) carries a written justification AND a measurable §5 test.
4. Treat omission as the catastrophic class; every unit gets a completeness/back-translation guard. Do not replace the whole-file omission-detector with a unit-local one without retaining a whole-file pass. Missing/unparseable STATUS always defaults to the conservative (error) value, never to pass.
5. New verification uses **external signals** and is capped (1–2 iters, accept-only-if-improved); no unbounded self-refinement, no self-certified apply-logs, no semantic "was-it-applied?" verifier. STATUS-malformation retries share the host loop's existing cap.
6. **Do not label LLM-in-context work "deterministic" (CC8).** Determinism requires a committed script actuator AND the tool grant to run it, or a redesign around LLM fallibility. This includes file copy/promotion and multi-file score arithmetic.
7. **Do not require selective partial-output writes (CC10).** Sentinel-anchoring schemes must work with full-reply writes and tolerate a scratchpad preceding STATUS.
8. **Do not anchor inter-agent handoffs on verbatim-excerpt matching (CC11/CC18).** Inter-agent contracts pass free-form prose + sentinels, not quote-located edit ledgers — and never quotes pinned to a draft snapshot a later step has overwritten.
9. **Do not assign literary-judgment tasks (semantic adequacy, mistranslation, distortion, cross-candidate ranking) to a Flash agent (CC12/CC20).** Such judgments belong to Pro or to an external numeric estimator (§4.11) consumed as a threshold, not as forwarded prose or a candidate selection.
10. **Do not justify glossary scoping by window pressure, do not filter by `sections` or chapter-lexicon presence, and do not write the shared glossary from a sampling/inference pass (CC13).**
11. **Do not open a write path from Stage B into any Stage-A artifact (CC14).** The glossary and `challenges.md` are frozen at the Stage-A barrier. Evolving per-chapter memory belongs in the forward-carried rolling summary (§4.8).
12. **Do not regress the mechanical Flash agents under the banner of "Flash-shaped prompting" (CC15).** No removal of the grep fast-path, no static in-prompt contrastive examples inside the in-loop budget, no self-reported scratchpad counts, no field-label renames without updating the downstream reader, no inline fixer markers into `draft/<f>`.
13. **Do not re-add the special-content layer or the out-of-loop scorer or any other already-shipped feature (CC16).** Diff the live files first.
14. **Do not fix a producer's defect inside a terminal consumer (CC17).** Detector over-flagging is fixed at the detector or a gated, report-rewriting post-filter — never by a triage scratchpad in `stray-phrase-fixer`.
15. **Do not forward a score/excerpt brief across the Stage-B mutation boundary (CC18).** A score signal lives at the §5 gate / escalation router as an external numeric threshold computed on the stabilized artifact.
16. **Do not gate on Flash-scorer noise (CC19).** No 1-point delta escalation, no draft-vs-final comparative re-run, no `REGRESSION_VERDICT:` sentinel, no per-issue resolution audit. The scorer is final-only and single-invocation.
17. **Do not propose in-pipeline best-of-N / multi-draft candidate selection (CC20).** It needs a winner-promotion write primitive the toolless orchestrator lacks, a discriminating ranker the Flash scorer is not, genuine candidate diversity thin Pro addenda do not yield, and it multiplies the dominant Pro cost. First-pass quality is improved by prompt/context, not by reranking drafts.
18. Keep the W1–W27 / CC ledger so coverage is auditable across loops.

## 10. Core Constraints Ledger (CC)

- **CC8:** Workhorse + Stage-A agents have `bash: deny` and no tokenizer/parser/script; the orchestrator is itself an LLM with no grep and **no file-write/copy primitive**. Decomposition needing a smaller unit-of-work must (i) commit a tag-aware, CJK-safe chunker/reassembler script (pays constraint 7), or (ii) prove whole-chapter overflow on real fixtures first. Single-objective decomposition remains available *at whole-file granularity* without seams.
- **CC9 (RESOLVED):** Per-agent model pinning is harness-asymmetric and accepted. opencode: `model:` frontmatter, provider-prefixed IDs (`google/gemini-3-{pro,flash}-preview`), **never** `timeout_mins`, omit `model:` for the five default agents. antigravity: no per-agent or workspace-default model field exists — model is operator-set in the UI and documented in `antigravity/AGENTS.md`. Verify both IDs resolve on models.dev before merge.
- **CC10:** STATUS sentinels are read out of full-reply artifact files. (i) STATUS is NOT guaranteed line 1 — omission-detector mandates a `<scratchpad>` before STATUS; reads must scan the whole file. (ii) No agent performs selective partial-output writes; any "reason in scratchpad but exclude it from the write" scheme is rejected. (iii) Scratchpad reasoning that forces full enumeration must be gated to the non-fast-path (ISSUES_FOUND), preserving the zero-hit grep → `STATUS: CLEAN` fast path. (iv) Absent/unparseable STATUS defaults to the conservative error value and re-invokes within the host loop's existing 3-iteration cap, never as a separate budget and never as a pass.
- **CC11:** The refinement→finalization pair is **Pro+Pro**, NOT Flash. Accountability machinery around critique is rejected: (i) **verbatim-excerpt anchors** are brittle — Pro models normalize typography and paraphrase when quoting, and `final-translator` has no grep; (ii) an **apply-log authored by `final-translator`** is self-certification, not verification; (iii) a **semantic "was-it-applied?" verifier** is an irreducibly Pro-level literary judgment; (iv) **rigid per-issue schemas / integer `ISSUE_COUNT` sentinels** fragment multi-clause diagnoses and add an integer-parse dependency with no malformation fallback. (b) Zero net saving: the filter agent must read the full glossary + full chapter. (c) `sections` is **backward provenance** — filtering on it strips recurring anchors from late chapters. (d) `local-lexicographer` extracts only chapter-*new* terms, so chapter-lexicon-presence filtering silently drops established names. (b) **Premise largely moot (fact 13):** Stage A completes for ALL chapters before any Stage B, so the glossary already holds every extracted term; the only residual is a proper-noun/neologism missed entirely *and* rendered divergently — narrow, not systematic.
