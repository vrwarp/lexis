# Lexis Redesign — 20-Loop Ideation / Adversarial-Critique / Improvement Ledger

This records the iterative redesign process the pipeline went through. Each loop: a focus is chosen (highest-leverage open problem), 3 diverse-lens agents ideate, 2 adversarial skeptics try to refute each idea, and a synthesis step integrates only survivors. Convergence shows as most loops rejecting all new ideas — the design stabilised by ~loop 12; loops 14-20 were quota-starved and did no substantive work.

## Open problems / recommended future work (not yet implemented)

- **[high] SP2** (decomposition): Primary-translator drafts whole chapter in one inference; no chunking/token budgeting (silent-truncation/lost-in-the-middle risk). Structural-boundary chunking BLOCKED by SP23 actuator gap. Plan: (a) verify on real fixtures whether whole-chapter calls overflow; (b) gate chunking behind a committed deterministic tag-aware CJK-safe chunker/reassembler; (c) meanwhile pursue single-objective decomposition at whole-file granularity. Overflow question is the unanswered prerequisite for SP5 glossary scoping.
- **[high] SP23** (decomposition): ACTUATOR GAP: no-bash agents (primary-translator, narrative-summarizer, translation-scorer) plus antigravity view/write/replace/list-only toolsets mean no agent can run a deterministic parser, tokenizer, token-counter, char-length gate, or byte-exact reassembler; repo has zero scripts/Python/Makefile. Every 'deterministic' step is executed by a stochastic LLM. Step 4.5 Adequacy-delta arithmetic is done by the ORCHESTRATOR reading two scorecards, but underlying scores remain Flash estimates. Blocks SP2, pre-screen, coverage gating, SP7 verify-applied, SP3 glossary-adherence, SP5 alias-filter, SP6 merge, SP13 post-hoc term check. stray-phrase-detector is the ONE Flash agent with grep/bash (sole in-agent actuator, regex-only).
- **[high] SP3** (quality-gates): Validation covers structural omission, stray-script residue, naturalness, and a Flash adequacy/fluency/style scorecard (run at draft and post-finalization) — but still no DETERMINISTIC semantic-accuracy/mistranslation or glossary-adherence HARD check. The translation-scorer is a weak self-estimate, not a hard gate. Add a back-translation/error-typed semantic validator and a glossary-adherence auditor (proper-noun/neologism deviation = hard fail). Glossary-adherence HARD FAIL is a deterministic presence/replace check blocked by SP23. A real semantic-validator gate still needs actuator-backed glossary check (SP23/SP13) or a calibrated QE metric (SP11) before it is a gate rather than another weak estimator.
- **[medium] SP4** (quality-gates): Pre-packaging quality gate exists (Phase 5): orchestrator reads every chapter's final.score.md, presents a per-chapter SCORE_VERDICT/Overall table, and blocks packaging on any FAIL until the user accepts the risk or requests remediation. Loops no longer exit purely on iteration count/status strings. RESIDUAL: the gate's signal is the uncalibrated Flash scorer (depends on SP11/SP18 calibration to be a true QE gate vs an advisory verdict); the layered string-pre-screen->QE/GEMBA->literary-judge stack remains aspirational (string pre-screen arithmetic blocked by SP23). Never tune the generator against COMET/BLEU.
- **[high] SP5** (context-memory): Context-window exhaustion: whole-chapter draft + full master_glossary.json + 5-7 context files may exceed usable window. translation-scorer is a SECOND full-context reader (source+draft+metadata+style+glossary+summary), invoked twice per chapter (4.0 draft, 4.5 final), increasing aggregate pressure. Adopt per-unit lexicon digests, frequency sort, small core glossary in system prompt. Every scoping mechanism is trapped between (a) deterministic alias-aware filter blocked by SP23 and (b) an LLM glossary-filter that reintroduces a stochastic correctness-critical step. Magnitude unverified (tied to SP2 overflow).
- **[high] SP6** (context-memory): Glossary is read-only in Stage B; dynamic-equivalence choices, register discoveries, first-occurrence freezes never propagate forward. Back-propagation rejected: a correctness-critical EDIT of master_glossary.json with no deterministic guard (SP23/SP5). translation-scorer is a candidate external signal to validate a proposed term decision but is itself a weak Flash estimate and not wired to feed back-prop. Reframe: ground feedback in an external signal + actuator-guarded append-mostly write, OR defer term revision to a post-finalization consistency/pruning pass (SP12/SP20).
- **[medium] SP7** (reflection-loops): native-critique is a single exhaustive pass and final-translator applies it in one shot, but the apply step is GROUNDED by an external delta: Step 4.5 re-invokes translation-scorer on final/<file> and the orchestrator computes the Adequacy delta vs the 4.0 draft score, flagging a >=2-point drop as a critique-regression human-gate. RESIDUAL: coarse after-the-fact regression detector, not a true per-issue verify-applied (SP23-blocked) and not yet a critique->apply->verify LOOP (cap 2, no re-apply on regression — halts for human); the 2-point threshold is conservative because the signal is a stochastic Flash estimate (SP11 calibration).
- **[high] SP8** (reflection-loops): Refinement is ungrounded self-critique with a fixed 3-iteration cap; weak estimators hallucinate past ~1 round and in-place patches introduce undetected regressions. translation-scorer runs at TWO points (4.0 draft, 4.5 final) giving a coarse end-to-end delta, but is NOT re-run PER omission/validation/critique ITERATION, so there is no accept-if-improved gate inside the loops — only a single draft-vs-final comparison. Wire the scorer as a per-iteration delta: accept a refined unit only if Overall (or Adequacy) improves, else revert; cap 1-2. Caveat: a Flash self-estimate may be too noisy as an accept/revert threshold without calibration (SP11).
- **[high] SP10** (epub-fidelity): ebook-packager has Flash parse and re-serialize OPF/nav XML, risking broken tags/entities and nav-vs-body label desync. Replace with deterministic XML mapping from precomputed values, xmllint validation, nav/heading reconciliation, and a round-trip-unzip structural check. Deterministic XML mapping depends on the actuator gap (SP23).
- **[medium] SP11** (model-tier-strategy): Best-of-N candidate generation + reference-free QE selection (the single biggest mid-tier quality lever) is absent; only one draft is ever produced. The translation-scorer is the reranking signal best-of-N needs, BUT it is single-candidate, uncalibrated, and (post 4.5) used only for draft-vs-final regression detection, not for ranking multiple candidates. Loop-12 EXPLORED and REJECTED three orchestrator-driven multi-invocation drafting variants (stratified, emphasis-differentiated, N-draft-at-Step-4.0): all produce correlated low-diversity candidates ranked by a noisy uncalibrated arbiter at 2-3x the most expensive Pro call, compounding SP5 pressure. NARROWED DIRECTION: the viable form needs true sampled diversity (temperature/seed, not prompt emphasis) AND a calibrated reranker (blend of xCOMET-QE adequacy + LiTransProQA-style literary score) BEFORE the lever pays off; the Flash scorer is only an interim proxy and calibration (SP18) is the gating prerequisite, not the candidate-generation mechanism. Operable at whole-chapter granularity today (no chunking dependency).
- **[medium] SP12** (quality-gates): No cross-chapter consistency audit: name drift, tonal whiplash, continuity breaks all ship. Add a post-finalization consistency-auditor over final/ + glossary that gates packaging. Phase 5 has a per-chapter scorecard gate but it is per-chapter quality, not cross-chapter consistency — complementary, not a substitute.
- **[high] SP13** (terminology-enforcement): Terminology relies on prompt-injected glossary promises a probabilistic decoder cannot guarantee. The translation-scorer does a 3-term glossary spot-check in its scratchpad (at draft and final), but that is a sampled self-report, not a deterministic post-hoc enforce. Adopt translate-then-revise with a deterministic post-hoc check/replace pass, inject whole inflected target forms, avoid constrained decoding. Determinism depends on SP23. SP3's glossary-adherence hard-fail is the same check from the validation side; resolve once via a shared actuator-backed term-presence pass that also serves SP5 scoping.

REMAINING GAP: no per-chapter asset-localization AUDIT verifying each SC-N element was actually rendered per its strategy in final/ (footnote markers preserved, table cells not merged, verse line breaks intact) — a post-finalization structural-presence check, deterministic if hard-gated (SP23-blocked), better homed in the SP12 consistency-auditor.
